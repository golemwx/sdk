## 发布依赖检查（如实登记）

- SDK 新契约 R02–R07 的真实修订链为 `f8b22b8 → 5cc02e8 → 1f37ac9 → 25e6c14 →
  6c77369 → 23a57e2`，当前仅在本地分支 `sdk-master`（相对 `origin/master` ahead 9），
  **未推送、未发布**；任务禁止 push/tag，因此本轮不能产生可被跨仓 `go get` 的新伪版本。
- `golem-plugins` 各模块 `go.mod` 固定的是旧契约伪版本
  `v0.0.0-20261030141904-d685cd30c027`（`d685cd3`）和
  `v0.0.0-20261029033730-7a6331800673`（`7a63318`）；本地联调依赖根 `go.work` 的
  `replace` 指向本地 `golem-sdk`。因此插件侧 `GOWORK=off` 的正式依赖校验在发布新修订前
  必然失败，属于跨仓阻断，不是 SDK 代码缺陷。
- 结论：下游（frame/plugins）可固定引用的真实修订仍需 owner 推送 `sdk-master` 后按
  `23a57e2` 生成伪版本或打 tag；在此之前不得伪造未发布版本，R23/R24/R25 的正式
  `GOWORK=off` 交叉构建均依赖该动作。SDK 自身的 `GOWORK=off` 验证不受影响（见下）。
