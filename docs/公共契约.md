## 一、总则

### 1.1 身份、ID 与时间

| 项 | 冻结表示 | 说明 |
| --- | --- | --- |
| 账号 username | `string` | 机器人账号的微信协议 username；等于配置 `owner_id` 时表示 Owner 本人 |
| 联系人/群/成员 username | `string` | 直接使用微信协议 username；`"不透明"` 只表示插件不得解析其内部格式 |
| 会话 ID | `string` | 私聊为对端联系人 username，群聊为群 username |
| 消息 ID | Go 和 SDK Proto 均为 `string` | core 的有符号/无符号 64 位正整数无损转换为十进制字符串；禁止用 `float64` 承载 |
| 业务时间 | `time.Time`（UTC） | Proto 使用 `google.protobuf.Timestamp`；JSON 使用 RFC3339 |
| 时长/期限 | `time.Duration` | Proto 使用 `google.protobuf.Duration` |
| 计数字段 | `int32`/`uint32`/`uint64` | 不参与算术的 ID 一律 `string` |

硬性约束：

1. 不新增账号本地数字 ID，不引入 `uint32 UIN` 作为公共身份
2. 时间统一 UTC 存储与传输；展示时区由插件自行决定
3. 消息 ID、`new_id`、群版本等可能超过 `2^53` 的整数在 JSON 中按字符串处理（见 9.3）

### 1.2 字段存在性

公共类型必须区分三种状态，不得用“零值即缺失”含糊处理：

| 状态 | Go 表示 | Proto 表示 | 业务含义 |
| --- | --- | --- | --- |
| 缺失 | `*T` 为 `nil` | 标量未设置（proto3 `optional`），消息字段为 nil | 本次数据没有携带该字段，保留旧值，不重置 |
| 显式空 | 非 nil 指针指向零值（如 `new("")`） | 字段已设置，值为空串/0 | 业务上明确为空，合并时覆盖旧值为空 |
| 有值 | 非 nil 且非零值 | 字段已设置 | 正常合并 |

适用规则：

1. 同步增量合并严格按上表执行；不得把“未携带”写成“清空”
2. 查询结果中不存在的对象返回 `NotFound`，不返回带零值字段的空结构
3. 可空业务字段（如备注、群公告）使用指针，避免空串与缺失混淆
4. 布尔字段使用指针或显式 `Set` 标记；`false` 不得被当成“未提供”
5. 领域表的 `?` 标量均使用 `*T`，如 `Nickname` 为 `*string`、`JoinedAt` 为 `*time.Time`；表中类型已写成指针时不再套一层
6. 可选集合需要区分缺失和空时，Go 使用 nil/非 nil 空切片，Proto 使用可选消息包装 repeated/bytes；不得依赖 repeated 自身保留存在性
7. 必填时间必须是合法非零时间，保留纳秒精度；可选时间为 nil 表示缺失。超出 Timestamp 范围返回 `InvalidArgument`，不截断、不用接收时间冒充源时间

### 1.3 枚举与 Unknown 零值

1. 所有公共枚举首值固定为 `Unknown`/`Unspecified`，数值为 0
2. 对端返回未知枚举值时，映射为 `Unknown` 并保留原始可用业务字段，不 panic、不透传原始协议对象
3. 枚举数值一旦发布不得复用；新增值追加在末尾
4. 字符串枚举（主题、能力名、权限名）使用小写点分或下划线形式，不做大小写归一

### 1.4 插件可见边界

1. 插件只见 `golem-sdk` 的纯业务类型；生成代码只存在于 `internal/wire`，不出现在插件业务签名
2. SDK 不导入 `github.com/golemwx/core`；任何核心协议字段、私有结构、CDN 解密材料都不得进入公共类型
3. 插件不得解析 username 前缀推断业务类型（`wxid_`、`gh_`、`@chatroom` 等），类型一律由 frame 归一后通过 `Contact.Kind`、`Conversation.Kind` 给出
4. 错误文本用于诊断，机器判断只依据 `Error.Category` 与 `Outcome`
5. frame 的 web 适配 DTO 为消费现有 core HTTP 所需的内部数据，限于 frame/api 接入边界；不能把 DTO 字段复制进 SDK 或业务对象。只有 lib 适配文件可以 import core

## 二、通用结构与语义

### 2.1 错误模型

```go
// Category 可机器判断的错误类别
type Category int

const (
	CategoryUnknown Category = iota
	CategoryInvalidArgument
	CategoryPermissionDenied
	CategoryNotFound
	CategoryAlreadyExists
	CategoryConflict
	CategoryFailedPrecondition
	CategoryResourceExhausted
	CategoryUnimplemented
	CategoryDeadlineExceeded
	CategoryCanceled
	CategoryUnavailable
	CategoryInternal
)

// Error 跨进程错误载体
type Error struct {
	Category     Category      // 唯一可靠的判断依据
	Operation    string        // 发生错误的业务方法名，如 "messages.send_text"
	InvocationID string        // 宿主分配的调用标识，未进入调用链时为空
	Outcome      WriteOutcome  // 写操作副作用结果；只读操作固定为 OutcomeNotApplicable
	Reason       string        // 脱敏诊断文本，不含 Token、正文、配置原文
	RetryAfter   time.Duration // 仅 ResourceExhausted/Unavailable 可能非零，提示最小退避
}
```

类别语义与调用侧行为：

| 类别 | 含义 | 调用侧行为 |
| --- | --- | --- |
| InvalidArgument | 参数或配置不合法 | 修正输入，不重试 |
| PermissionDenied | 权限不足、凭据错误、跨账号引用 | 不重试 |
| NotFound | 对象、能力、租约不存在 | 按业务处理 |
| AlreadyExists | 重复注册、租约被占用 | 刷新状态后处理 |
| Conflict | revision 或并发写冲突 | 重新读取后重试 |
| FailedPrecondition | 未登录、未初始化、禁用、已过期、状态不允许 | 等状态改变 |
| ResourceExhausted | 队列、并发、大小限额 | 显式退避，不无限排队 |
| Unimplemented | 对端未实现该方法或能力 | 不伪造空成功 |
| DeadlineExceeded | 期限到达 | 已提交且无法确认结果的写操作置 `OutcomeUnknown` |
| Canceled | 调用方取消 | 同上；提交前已拒绝的写为 `OutcomeFailed` |
| Unavailable | core 或插件暂不可用 | 仅安全读取可有界重试 |
| Internal | 实现错误 | 记录脱敏诊断，不重试 |

冻结规则：

1. `Category` 是唯一机器判断依据；不得匹配 `Reason` 文本做分支
2. 空值/未登录/未初始化必须区分：未初始化返回 `FailedPrecondition` 且 `Reason` 明确“未初始化”，不返回空列表
3. 插件未实现的方法返回 `Unimplemented`，不返回零值成功
4. `*Error` 实现 Go `error` 接口，SDK 支持 `errors.As`；`Reason` 只用于展示，初始化状态、错误类别均不通过匹配该文本判断

### 2.2 查询与分页

```go
// PageRequest 有界分页请求
type PageRequest struct {
	Limit  int    // 0 表示使用默认值；默认 100，最大 1000，超过按 1000 处理
	Cursor string // 空表示从头开始；由上一次 Page.NextCursor 原样回传
}

// Page 有界分页结果
type Page[T any] struct {
	Items        []T
	NextCursor   string       // 空表示没有更多
	Total        int64        // -1 表示未知；仅统计当前授权范围
	Completeness Completeness // 当前查询范围的数据完整性，与是否还有下一页无关
}
```

1. 默认页长 100，最大 1000；不在一次 RPC 返回无上限集合
2. `Cursor` 不透明，插件不得解析或构造
3. 空结果与未初始化区分：空结果返回 `Items` 为空切片（非 nil）且 `NextCursor` 为空；未初始化返回 `FailedPrecondition`
4. 本地查询不因缺失隐式触发网络请求
5. 负数 Limit 返回 `InvalidArgument`；游标绑定账号、查询条件、授权范围及数据修订，条件不符返回 `InvalidArgument`，已失效返回 `FailedPrecondition`
6. Find 按昵称或备注做字面子串匹配，空查询等同 List，不做 username 格式推断；按 Username 字典序稳定分页

### 2.3 未初始化与数据完整性

| 状态 | 表示 | 行为 |
| --- | --- | --- |
| 未初始化 | `FailedPrecondition`，`Reason` = "not initialized" | 提示显式 `Refresh`，不自动回源 |
| 不完整 | 正常返回，`Completeness = Incomplete` | 可用于展示，不得用于授予管理权限 |
| 完整空集合 | 正常返回空集合，`Completeness = Complete` | 是有效结果，不得当作持续回源理由 |

授权相关规则：群成员角色、Owner 判断只能来自已确认字段；资料不完整时不得据此授予管理权限。

```go
// Completeness 当前资料或查询范围的完整性
type Completeness int

const (
	CompletenessUnknown Completeness = iota
	CompletenessIncomplete
	CompletenessComplete
)
```

Contact、Room、Member 均必有 `Completeness Completeness` 字段。它表示该对象所需资料是否已完成初始化；Page 的同名字段表示查询范围是否完整，不表示可选资料全部有值。完整空群成员集合可为 Complete；局部变更不能自行证明成员全量完整。

### 2.4 部分成功

1. 批量操作返回逐项结果，不把部分成功折叠为整体成功
2. 逐项结果至少包含 `SubjectID`、`Outcome`、`Error`
3. 框架只在明确全部成功时返回 nil error；存在失败项时，按输入顺序取首个失败的类别作为整体 error，保留逐项结果（包括 `Internal`）
4. 写操作中出现 `OutcomeUnknown` 的项，调用方不得自动重试

```go
// BatchResult 批量操作结果，读写均保留逐项状态
type BatchResult[T any] struct {
	Items []BatchItem[T] // 顺序与输入一致
}

// BatchItem 单项结果
type BatchItem[T any] struct {
	SubjectID string
	Value     T
	Outcome   WriteOutcome
	Error     *Error // 成功时为 nil
}
```

只读批量项失败时 Value 为 T 的零值，只在 Error=nil 时读取它；不得让失败值覆盖已有资料。BatchResult.Items 包装消息需保留显式空集合语义。

### 2.5 写结果与 OutcomeUnknown

```go
// WriteOutcome 写操作副作用结果
type WriteOutcome int

const (
	OutcomeUnspecified   WriteOutcome = iota // 未知枚举零值，绝不能表示成功
	OutcomeNotApplicable                     // 只读操作
	OutcomeSucceeded                         // 上游明确成功
	OutcomeFailed                            // 确认未完成目标写入，如提交前拒绝
	OutcomeUnknown                           // 超时/取消/响应丢失，可能已生效
)
```

1. 发送、撤回、改资料等写操作已提交后超时、取消或响应损坏时，无法确认目标结果则返回 `OutcomeUnknown`，框架不自动重试；提交前验证或授权失败为 `OutcomeFailed`
2. `OutcomeUnknown` 不得被转换为成功或失败；调用方只能提示或稍后核对
3. 只读操作失败固定 `OutcomeNotApplicable`
4. 成功时必须给出可校验的业务结果（如 `SendReceipt`），不返回空成功
5. `Category` 与 `Outcome` 独立：`Internal` 可以伴随 `OutcomeUnknown`；缺失/未知 Outcome 不得降为确定失败或成功。语义上只读的 Refresh，其逐项 Outcome 为 `OutcomeNotApplicable`，成功与否由 Error 和 Value 判定；已取得且可验证的资料可以合并，失败项保留原值

### 2.6 媒体引用

```go
// MediaKind 媒体种类
type MediaKind int

const (
	MediaKindUnknown MediaKind = iota
	MediaKindImage
	MediaKindVoice
	MediaKindVideo
	MediaKindFile
	MediaKindEmoji
	MediaKindOther // 已知消息类型但暂未归类的媒体
)

// MediaRef 宿主管理的媒体引用
type MediaRef struct {
	Token     string    // 不透明随机 token，跨进程可传递但不可解析
	Kind      MediaKind // Image、Voice、Video、File、Emoji、Other
	FileName  string    // 仅用于展示与扩展名判断，不用于拼接路径
	SizeBytes int64     // -1 表示未知
	ExpiresAt time.Time // 失效后使用返回 FailedPrecondition
}
```

1. token 绑定账号、调用方实例和资源范围；未经宿主授权转交的跨账号、跨实例使用返回 `PermissionDenied`
2. 不公开 CDN 文件 ID、AES 密钥、解密材料或原始协议字段
3. 插件不得向框架提交宿主本地路径；上传由插件自行打开文件并传字节流
4. 引用失效返回 `FailedPrecondition`，不当成 `NotFound`
5. 能力提供者返回媒体时，由 frame 校验后向本次调用方重新签发引用，权限取双方范围交集；不直接复用提供者 token。调用方可通过 Download 读取，或通过 SendMedia 的 Ref 发送

### 2.7 撤回引用

```go
// RevokeRef 宿主管理的撤回引用
type RevokeRef struct {
	Token     string // 不透明 token
	ExpiresAt time.Time
}
```

1. `RevokeRef` 只由 `SendReceipt` 返回，绑定账号与会话；插件不能自行构造
2. 撤回所需的协议参数（服务端消息 ID、客户端消息 ID、创建时间）由宿主保存，不进入公共类型
3. 引用过期、重启后不可恢复返回 `FailedPrecondition`；跨账号、跨实例或超出授权范围返回 `PermissionDenied`
4. 消息 ID 无法唯一确定撤回目标时，不返回 `RevokeRef`，`SendReceipt.RevokeRef` 为 nil

## 三、领域模型

以下字段为冻结定义。`+` 表示必有，`?` 表示可空（缺失与显式空按 1.2 区分）。

### 3.1 Account

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| Username | `string` | + | 机器人账号协议 username；仅在 Unlogged/Unknown 时允许空 |
| Nickname | `string` | ? | 账号昵称；core 未提供时为空 |
| Online | `bool` | + | 当前是否可承载在线业务 |
| Status | `AccountStatus` | + | 见下表 |
| UpdatedAt | `time.Time` | + | 本快照生成时间 |

```go
// AccountStatus 账号业务状态
type AccountStatus int

const (
	AccountStatusUnknown  AccountStatus = iota
	AccountStatusUnlogged               // 未登录
	AccountStatusLoggedIn               // 已登录但不在线
	AccountStatusOnline                 // 在线，可承载业务
	AccountStatusOffline                // 已离线
)
```

规则：`Online=true` 与 `AccountStatusOnline` 必须一致；不一致视为实现错误。`Account.Current` 可在未登录时返回 Username 为空的状态快照，不能因此把成功取得的“未登录”状态变成查询失败。在线状态 username 为空则返回 `Internal`。需要账号就绪的业务方法在非在线状态返回 `FailedPrecondition`。

### 3.2 Conversation

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| AccountUsername | `string` | + | 机器人账号 username |
| Kind | `ConversationKind` | + | `Direct` 或 `Room` |
| ID | `string` | + | 私聊为对端 username；群聊为群 username |

```go
// ConversationKind 会话种类
type ConversationKind int

const (
	ConversationKindUnknown ConversationKind = iota
	ConversationKindDirect
	ConversationKindRoom
)
```

1. `ID` 在私聊中是对端联系人，不是群
2. 会话租约键为 `(AccountUsername, ID)`；`Actor.Username` 不参与租约键
3. `KindUnknown` 的会话不得用于 `Sessions.Acquire`

### 3.3 Actor

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| Username | `string` | + | 实际发言者的协议 username，不为空 |
| DisplayName | `string` | ? | 群内显示名或昵称，仅用于展示 |
| Resolution | `ActorResolution` | + | 解析结果与失败原因 |

```go
// ActorResolution 实际发言者解析结果
type ActorResolution int

const (
	ActorResolutionUnknown     ActorResolution = iota
	ActorResolutionResolved                    // 成功解析
	ActorResolutionDirect                      // 私聊，发言者取实际 sender；出站时为账号本人
	ActorResolutionSystem                      // 系统消息，无发言者
	ActorResolutionParseFailed                 // 群消息缺少可解析的发言者前缀
	ActorResolutionNoSender                    // 源数据没有发送者字段
)
```

冻结规则（来自设计 6.1 与 12.1）：

1. 私聊取源消息发送者 username，标记 `Direct`；本人发出时 Actor 是机器人，不是对端
2. 群聊入站消息的发送者是群 username；实际成员 username 从消息正文前缀按协议规则解析，标记 `Resolved`；本人发出的群消息在已确认 sender 为账号时 Actor 是机器人
3. 解析失败、系统消息或没有明确发送者时，`Message.Actor` 为 nil 并把原因写入 `Message.ActorResolution`；禁止把群 username 冒充为操作者
4. Owner 判断只使用 `Actor.Username`；`Actor` 为 nil 时一律不是 Owner
5. `DisplayName` 不能用于权限判断
6. 系统消息识别优先于成员前缀解析；Actor 非 nil 时两个 Resolution 字段必须一致且 Username 非空。方向无法确认时不据候选前缀授予 Owner 权限

### 3.4 Contact

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| Username | `string` | + | 联系人协议 username |
| Kind | `ContactKind` | + | 见下表 |
| Nickname | `string` | ? | 昵称 |
| Remark | `string` | ? | 本人设置的备注；显式空表示清除 |
| AvatarURL | `string` | ? | 头像地址（大图优先） |
| Alias | `string` | ? | 微信号别名 |
| UpdatedAt | `time.Time` | + | 本记录最后更新时间 |
| Completeness | `Completeness` | + | 该联系人资料初始化完整性 |

```go
// ContactKind 联系人类型
type ContactKind int

const (
	ContactKindUnknown  ContactKind = iota
	ContactKindFriend               // 普通好友
	ContactKindRoom                 // 群聊，同时也是群的联系人视图
	ContactKindOfficial             // 公众号
	ContactKindSelf                 // 机器人账号自身
)
```

`ContactKind` 与群的关系（冻结）：

1. 群的联系人视图（名称、备注、头像、更新时间）属于 `Contact`，`Kind = ContactKindRoom`，与 `Room` 使用同一 username
2. 群专属详情（Owner、公告、info_version）只在 `Room` 中
3. 持久化时，群的公共联系人信息与群专属详情都写入 `contact.json`；成员信息写入 `chatroom.json`
4. 不存在只含成员的“群对象”；`Get(roomUsername)` 与 `Room` 查询可分别返回联系人与群详情

判定来源统一以映射文档 4.3 为准：Self、已确认群证据、公众号验证位、已确认普通联系人；证据冲突或不足为 Unknown。core 字段存在不等于非零值，更不等于已确认类型；插件不解析前后缀或私有标志位。

### 3.5 Room

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| Username | `string` | + | 群协议 username |

### 3.7 Message

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| ID | `string` | + | 服务端消息 ID |
| Conversation | `Conversation` | + | 所属会话 |
| Actor | `*Actor` | ? | 实际发言者；解析失败为 nil |
| ActorResolution | `ActorResolution` | + | 与 `Actor` 同步填写 |
| Direction | `Direction` | + | 见下表 |
| Kind | `MessageKind` | + | 见下表；未知类型为 `Unknown` |
| CreatedAt | `time.Time` | + | 服务器创建时间（UTC） |
| Text | `*string` | ? | 文本正文或引用文本；非文本类型为 nil |
| Mentions | `[]string` | ? | 被 @ 的 username 列表，顺序保持 |
| Quote | `*Quote` | ? | 引用摘要；首期不产出 |
| Media | `*MediaRef` | ? | 媒体引用；首期同步事件不产出，见第 9 章 |

```go
// Direction 消息方向
type Direction int

const (
	DirectionUnknown  Direction = iota
	DirectionInbound            // 他人发给机器人
	DirectionOutbound           // 机器人自己发出
)

// MessageKind 消息种类
type MessageKind int

const (
	MessageKindUnknown MessageKind = iota
	MessageKindText
	MessageKindImage
	MessageKindVoice
	MessageKindVideo
	MessageKindFile
	MessageKindEmoji
	MessageKindLink
	MessageKindApp
	MessageKindNote
	MessageKindRecord
	MessageKindMusic
	MessageKindPosition
	MessageKindNameCard
	MessageKindSystem

// Quote 引用摘要
type Quote struct {
	MessageID     string // 被引用消息 ID；未知时为空
	ActorUsername string // 被引用消息发言者
	Digest        string // 有界预览文本，最长 200 个字符
}
```

冻结规则：

1. `Text` 只承载已归一的业务文本；未知类型仍保留 ID、会话、时间等已确认字段，但不得通过 Text 透传 core XML、CDN 参数或原始协议对象
2. 本人发出的消息标记 `DirectionOutbound`，默认不自动回复；这一判断由插件按业务需要执行，框架不额外过滤
3. Mentions 只包含 username，不含昵称；nil 表示来源未携带或尚未确认，非 nil 空切片表示已确认没有 @
4. `Quote` 首期为 nil（core 首期未提供稳定引用解析），T27 落实后再填充；插件必须先判空
5. `Media` 首期为 nil；同步事件只携带消息 ID 与元数据，T26 落实媒体引用后再填充
6. 同一消息只产生一个 `Message`；frame 不按 ID、正文或时间做二次去重（去重由 core 完成）

### 3.8 SendReceipt

| 字段 | 类型 | 存在性 | 语义 |
| --- | --- | --- | --- |
| MessageID | `string` | + | 上游返回的服务端消息 ID；Unknown 结果允许空 |
| Conversation | `Conversation` | + | 实际接收会话 |
| SentAt | `time.Time` | + | 发送完成时间（UTC） |
| Outcome | `WriteOutcome` | + | 固定为 `OutcomeSucceeded` 或 `OutcomeUnknown` |
| RevokeRef | `*RevokeRef` | ? | 可撤回时的引用 |

1. 成功返回必须带非空 `MessageID`；上游未返回完整服务端 ID 时返回 `Internal`，若可能已经发送则 OutcomeUnknown，不返回空成功，也不使用另一类本地 ID 顶替
2. `OutcomeUnknown` 时 `MessageID` 可能为空，`RevokeRef` 为 nil
3. 同一业务请求不自动重发；重复发送由调用方决定
4. 确定发送失败返回 nil receipt + 非 nil Error，OutcomeFailed 放在 Error 上；不返回 OutcomeFailed 的 SendReceipt。结果未知可返回仅含已知字段的 receipt + 非 nil Error，二者 Outcome 均为 Unknown；nil error 必须伴随完整 Succeeded receipt

## 四、Host 能力

需要宿主能力的插件嵌入零值 `plugin.Base`，SDK 在 Initialize 完成安全反向就绪确认后自动绑定实例专属 `Host`，通过 `p.Host` 字段获取。绑定不依赖 Loader；`OnLoad(ctx)` 仅处理业务初始化。构造和 Descriptor 阶段尚未绑定，禁用保留绑定，卸载回调期间仍可使用；回调结束或连接失效后关闭连接、取消后台上下文，字段保留已失效的句柄。SDK 使用私有接口识别 Base，不使用全局变量、反射或 `unsafe`；绑定不授予用户身份或绕过宿主授权。

Base 首次使用后不得复制或复用到其他连接；插件以指针交给 Serve。Host 字段仅供初始化后的回调读取，插件不得改写；失效时 SDK 不改写该字段，避免与业务读取发生竞争。纯本地测试可通过 `plugin.NewBase(fakeHost)` 构造替身，正式启动不能预先绑定测试 Host。

```go
// Host 宿主能力集合
type Host struct {
	Messages  MessagesClient  // 消息收发
	Contacts  ContactsClient  // 联系人查询
	Chatrooms ChatroomsClient // 群与成员查询
	Sessions  SessionsClient  // 会话租约
	Caller    CallerClient    // 跨插件调用
	Config    ConfigClient    // 自身业务配置
	Account   AccountClient   // 当前账号

	DataDir string // 该插件的绝对数据目录 plugins/data/<plugin_name>
}
```

通用签名规则（冻结）：

1. 所有涉及 I/O 的方法第一参数为 `context.Context`，最后返回 `error`
2. 方法内不得使用 `context.Background()` 替换调用方 context
3. `OnLoad`/`OnEnable` 的 context 只在该次生命周期调用内有效；后台任务必须使用 `Host.TaskContext()` 派生的 context
4. 返回的集合必须是深副本，插件修改返回值不改变宿主状态

### 4.1 MessagesClient

```go
type MessagesClient interface {
	// SendText 发送文本消息，mentions 为被 @ 的 username
	SendText(ctx context.Context, conversation Conversation, text string, mentions []string) (*SendReceipt, error)
	// SendMedia 发送媒体消息，reader 由调用方打开并负责关闭
	SendMedia(ctx context.Context, conversation Conversation, media MediaUpload) (*SendReceipt, error)
	// Reply 以引用回复形式发送文本；首期未实现时返回 Unimplemented
	Reply(ctx context.Context, conversation Conversation, quote Quote, text string) (*SendReceipt, error)
	// Revoke 撤回本人发出的消息
	Revoke(ctx context.Context, ref RevokeRef) error
	// Download 下载消息媒体，返回受限的读取流
	Download(ctx context.Context, media MediaRef) (io.ReadCloser, error)
}

// MediaUpload 插件提供的媒体字节与元数据
type MediaUpload struct {
	Kind     MediaKind
	FileName string // 仅展示与扩展名判断
	Size     int64  // -1 表示未知
	Reader   io.Reader
	Ref      *MediaRef     // 与 Reader 二选一；允许发送能力渲染得到的媒体
	Voice    *VoiceOptions // Kind=Voice 时必填
}

// VoiceOptions 业务音频参数，不使用 core 的数值枚举
type VoiceOptions struct {
	Duration time.Duration // 必须为正，精确到毫秒，且毫秒数不超过 int32
	Encoding VoiceEncoding
}

// VoiceEncoding 公共音频格式
type VoiceEncoding int

const (
	VoiceEncodingUnknown VoiceEncoding = iota
	VoiceEncodingAMR
	VoiceEncodingSPEEX
	VoiceEncodingMP3
	VoiceEncodingWAVE
	VoiceEncodingSILK

```

Reader 的原始文件由插件关闭，SDK 不在本地进程关闭调用方 reader；lib 适配器另包 `io.ReadCloser`，由 core 关闭宿主一侧的流。Download 的流由调用方关闭，取消或 Close 都终止底层传输并释放额度。Ref 与 Reader 同时为空或同时非空返回 InvalidArgument；Kind 必须与引用一致。T26 实现宿主管理流式引用所需的上传辅助入口和流控制，不能把本地路径或全部文件塞进一元 RPC。

### 4.3 ChatroomsClient

```go
type ChatroomsClient interface {
	// Get 查询群详情；未初始化返回 FailedPrecondition
	Get(ctx context.Context, roomUsername string) (*Room, error)
	// Members 有界分页列出群成员
	Members(ctx context.Context, roomUsername string, page PageRequest) (*Page[Member], error)
	// Member 查询单个群成员
	Member(ctx context.Context, roomUsername, userUsername string) (*Member, error)
	// Refresh 显式初始化或刷新指定群的资料与成员，需 chatroom.write 权限
	Refresh(ctx context.Context, roomUsername string) (*ChatroomRefreshResult, error)
}

// ChatroomRefreshResult 群刷新结果，成员从本地 Store 有界分页读取
type ChatroomRefreshResult struct {
	Room    *Room                // 联系人/扩展信息均失败时 nil；否则是合并后的局部/完整快照
	Members *Page[Member]        // 名单成功时返回默认 100 条的首个本地页；失败为 nil
	Stages  []RefreshStageResult // 固定 contact、room_info、members 三项，按此顺序
}

// RefreshStageResult 单个上游只读阶段的结果
type RefreshStageResult struct {
	Name    string       // contact / room_info / members
	Outcome WriteOutcome // 固定 OutcomeNotApplicable
	Error   *Error       // 成功时 nil，未执行/失败时明确错误
}
```

两个 Refresh 均为显式只读上游并更新本地资料，不发送业务写请求。Contacts.Refresh 必须给出 1—1000 个唯一 username，逐项结果顺序与输入相同；空输入不是“刷新全部”。首次通讯录初始化由 frame 内部调用全量列表入口，不向插件开放无界全量 Refresh。

Chatrooms.Refresh 按 contact → room_info → members 三个阶段访问 core；剩余期限内某阶段失败可继续独立阶段。Stages 保留每阶段错误，整体 error 取首个失败类别；未执行的阶段明确记录取消/期限/前置错误，不视为成功。只合并已确认字段，名单失败时 Members=nil、旧名单不清空；成功名单写入本地后返回默认首个有界页，NextCursor 可交 Chatrooms.Members 续查。完整空群为非 nil 的空页且 Complete。

成员额外联系人详情 MemberDetail 不属于插件 Chatrooms.Refresh 的隐式第四阶段；ListMembers 已提供成员 username、昵称和群内显示名。必要初始化/明确业务补全由 frame 内部另行按最多 20 人一批调用 MemberDetail，并记录逐项失败；不能因缺失昵称自动回源。Completeness 只由已确认的初始化/完整名单证据推进，刷新失败不清除旧资料，也不能把失败结果标成一次成功全量快照。

```go
type SessionsClient interface {
```

### 4.5 CallerClient

```go
type CallerClient interface {
	// Call 按能力名调用，由 frame 选择提供者；不指定插件 ID
	Call(ctx context.Context, request CallRequest) (*CallResult, error)
}
```

冻结规则：无可用提供者返回 `NotFound`；无权调用该能力返回 `PermissionDenied`；已选实例失效返回 `Unavailable`；调用开始后不自动改投其他提供者；业务错误旁的有效部分结果必须与错误一起返回，不得丢弃或触发改投；最大调用深度 8，重复进入同一实例拒绝（`FailedPrecondition`）。实际提供者按自身策略的权限和资源范围执行宿主调用；原调用的用户、会话、观察/会话来源、调用链和期限继续继承，调用方权限不替代提供者权限。

后台调用必须同时使用 `background.run`、`capability.call`、具体能力名和联系人/整群白名单。插件通过 `capability.WithBackgroundTarget(Host.TaskContext(), target)` 指定目标；SDK 只认可当前启用周期 TaskContext 中由宿主签发的私有随机令牌，普通业务 context 剥离取消后不能升级为后台身份。禁用、卸载、断连和重启用都会撤销旧令牌，重新启用必须换新令牌。

宿主调度层也接受 `CapabilityName = background.run` 的 JSON 包装，供没有公开 SDK 上下文的受信任务使用：`{"capability_name":"text.to.image","payload":{...}}`。只有显式标记为后台来源且同时具备 `background.run` 权限的作用域可以进入该包装，空 Actor 或普通 invocation 不能据此升级。外层 ContentType 固定 application/json，内层遵循实际能力契约；仍须声明并授权 background.run 与实际能力，不能嵌套 background.run。

```go
)
```

冻结规则：`Save` 只是 CAS 接受，不代表运行态已切换；不能修改 enable、权限、优先级或其他插件节；不得在当前 handler 内等待自己提交的配置变成 active。

### 4.6.1 配置提供者接口（Defaults/Validate/Apply）

插件通过实现可选小接口参与配置校验与应用，三者互相独立：

```go
// ConfigDefaulter 返回业务默认配置，不触发副作用
type ConfigDefaulter interface {
	// ConfigDefaults 返回默认 TOML；宿主在新插件首次生成配置节时使用
	ConfigDefaults() []byte
}

// ConfigValidator 纯校验候选配置，不改变运行状态
type ConfigValidator interface {
	// ConfigValidate 校验候选配置；失败返回 InvalidArgument，旧配置保持 active
	ConfigValidate(ctx context.Context, candidate []byte) error
}

// ConfigApplier 以原子切换方式应用候选配置
type ConfigApplier interface {
	// ConfigApply 先准备候选资源，准备成功后一次性切换；失败时旧资源与旧配置完整保留
	ConfigApply(ctx context.Context, candidate []byte) error
}
```

冻结语义：

1. `ConfigDefaults` 可被多次调用，必须幂等且无副作用；不返回默认值时宿主写入空配置节
2. `ConfigValidate` 不得改变当前运行状态，不得发起写操作；只做纯校验
3. `ConfigApply` 必须先准备资源、再切换；**只有保证确定失败时**才允许保留旧 active 继续运行
4. `ConfigApply` 超时、响应丢失或进程崩溃时结果未知：宿主必须停止并重建实例，不得只保留旧 revision 数字冒充回滚成功
5. 重建以持久 desired 为输入重新校验；不通过则 `ApplyStatus=Failed`
6. Apply 前宿主关闭该实例新业务准入并排空实际执行，使用与禁用相同的屏障；控制 RPC 有独立期限
7. 插件不得在当前 handler 内等待自己提交的配置变成 active，应通过 `Config.Snapshot` 的 `ActiveRevision`/`ApplyStatus` 观察
8. 缺少 Defaults 时不注入业务默认值，缺少 Validate 时仅做 TOML/大小校验。没有 Apply 的插件不能在启用期间更改业务配置：Save 返回 FailedPrecondition，管理员可排空重建实例；不能只推进 ActiveRevision 冒充已应用
9. `ConfigApply` 只有返回 `OutcomeFailed`（插件明确保证旧资源完整）或 `Unimplemented`（无副作用）才算确定结果；其余错误按 `OutcomeUnknown` 处理

宿主完成 Apply 后必须调用 `ConfigResume`，而不是自动重开业务准入。`rpc.ConfigProvider`
提供 Defaults、Validate、Apply、Resume 和 ApplyAndResume 包装；恢复时携带同一启用
周期的新后台令牌，且仅对仍加载、已启用并处于排空态的实例生效。**ConfigApply 自身
不恢复准入。**

## 五、插件接口与 Descriptor

### 5.1 接口组合

```go
// Plugin 插件基础契约，必须实现
type Plugin interface {
	Descriptor() Descriptor
}

// Loader 可选的业务加载初始化，Host 已由 SDK 绑定
type Loader interface {
	OnLoad(ctx context.Context) error
}

// Enabler 启用期后台任务
type Enabler interface {
	OnEnable(ctx context.Context) error
}

// Disabler 停止后台任务并释放启用期资源
type Disabler interface {
	OnDisable(ctx context.Context) error
}

// Unloader 释放加载期资源
type Unloader interface {
	OnUnload(ctx context.Context) error
}

// EventHandler 事件处理
type EventHandler interface {
	OnEvent(ctx context.Context, event Event) (EventResult, error)
}

// CommandHandler 命令处理
type CommandHandler interface {
	OnCommand(ctx context.Context, command Command) (CommandResult, error)
}

// CapabilityHandler 被调用能力
type CapabilityHandler interface {
	OnCall(ctx context.Context, request CallRequest) (CallResult, error)
}
```

1. 未实现的生命周期接口视为无操作，不要求写空方法
2. 声明了订阅、命令或被调用能力却没有实现对应业务接口时，`Initialize` 失败（`FailedPrecondition`），不静默降级
3. 事件处理返回错误不终止后续插件，除非已是最后一个

`rpc.ClientOptions.BeforeLoad` 由宿主可选提供，在 Initialize/ReverseReady 完成后、
OnLoad 前执行，用于生成、校验并持久化首次业务配置。`ConfigTimeout` 独立限制每次
配置控制调用，不占用普通业务期限。任一回调失败都会回到统一启动清理路径。

### 5.2 Descriptor

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| ID | `string` | `plugin_name`，小写字母/数字/下划线/短横线，长度 1—64 字节；必须与可执行文件名推导值一致 |
| Name | `string` | 展示名，非唯一身份 |
| Description | `string` | 展示与诊断 |
| Author | `string` | 展示 |
| Version | `string` | 可选；仅展示，不参与握手、加载或能力路由 |
| RequestedPermissions | `[]Permission` | 请求的权限，不等于已获授权 |
| Subscriptions | `[]Subscription` | 主题、模式（respond/observe）、优先级 |
| Commands | `[]CommandSpec` | 路径、参数 schema、权限要求 |
| Capabilities | `[]CapabilitySpec` | 提供的能力名与输入输出约定 |
| UsesCapabilities | `[]string` | 需要调用的能力名；用于授权与诊断，不指定提供者 |
| HasConfigDefaults | `bool` | SDK 管理；表示实现 ConfigDefaulter，插件设置会被 Describe 覆盖 |
| HasConfigValidate | `bool` | SDK 管理；表示实现 ConfigValidator，插件设置会被 Describe 覆盖 |
| HasConfigApply | `bool` | SDK 管理；表示实现 ConfigApplier，插件设置会被 Describe 覆盖 |

```go
// SubscribeMode 订阅模式
type SubscribeMode int

const (
	SubscribeModeUnknown SubscribeMode = iota
	SubscribeModeRespond               // 参与普通响应链
	SubscribeModeObserve               // 只观察，不影响路由
)

// Permission 权限标识，取值为 5.3 表中的字符串常量
type Permission string

// ArgType 命令参数类型
type ArgType int

const (
	ArgTypeUnknown ArgType = iota
	ArgTypeString
	ArgTypeInt
	ArgTypeFloat
	ArgTypeBool
	ArgTypeEnum
)

type Subscription struct {
	Topic    string        // 见第六章
	Mode     SubscribeMode // Respond 或 Observe
	Priority int           // 数值越小越优先；同优先级按 PluginID 稳定排序
}

type CommandSpec struct {
	Path       []string   // 完整路径，如 {"golem","help"} 之外的普通命令
	Args       []ArgSpec  // 显式 schema，不使用反射
	Permission Permission // 调用所需权限，Owner 管理命令除外
	Help       string
}

// CapabilitySpec 提供的能力名与输入输出约定
type CapabilitySpec struct {
	Name          string // 能力名，如 text.to.image；不带版本后缀
	InputType     string // 参数 ContentType，首期固定 application/json
	OutputType    string // 结果 ContentType，如 image/png、application/json
	Description   string // 参数与结果约定的说明
	MaxInlineSize int    // 内联结果上限，0 表示使用默认 256 KiB，不得大于 256 KiB
}

type ArgSpec struct {
	Name     string
	Type     ArgType // String、Int、Float、Bool、Enum
	Required bool
	Default  string
	Enum     []string
	Min, Max *float64
	Help     string
}
```

命令校验 API（T15 固定）：

```go
func command.ValidateSpec(spec command.CommandSpec) error
func command.ValidateArgs(spec command.CommandSpec, supplied map[string]string) (map[string]string, error)
func command.Bind(spec command.CommandSpec, supplied map[string]string, target any) error
```

1. 路径至少包含一个完整段；路径段和参数名使用 ASCII 字母或数字开头，后续可含字母、数字、`-`、`_`，不含 `/`、空白或选项前缀；首段 `golem` 为框架保留
2. 空权限表示命令不额外要求 Host 权限；非空权限必须属于 5.3 的首期权限表
3. String 不使用范围或枚举约束；Int/Float 可使用有限闭区间，其中 Int 区间必须至少包含一个 Int64 可表示整数；Bool 不使用范围或枚举；Enum 必须提供不重复的候选值且不使用范围
4. 非空 Default 必须能按类型解析并满足范围或枚举；既有 `Default string` 没有存在位，因此空字符串固定表示未声明默认值
5. `ValidateArgs` 拒绝未知参数和缺失必填参数；必填优先于 Default。已提供值按 Int64、Float64、Bool 或 Enum 校验，拒绝整数/浮点溢出、NaN、Inf 和越界
6. 显式空字符串是“已提供”：String 接受，Enum 仅在候选值包含空字符串时接受，数值和 Bool 拒绝。输出为输入 map 的独立副本；可选参数补非空 Default，无 Default 的可选 Bool 补 `"false"`，其余缺省参数不写入结果
7. SDK 在插件侧 `Describe` 缓存声明前校验，并由 `Initialize` 复用该结果；宿主侧在 `rpc.Start` 收到 Describe 结果后再次校验，不信任插件自行实现的传输端。完整路径在同一 Descriptor 中重复返回 `AlreadyExists`。参数级 schema 错误（非法或重复参数名、类型、默认值、范围、枚举）均包含被拒参数名和修复方向
8. 位置参数继续独立保存在 `Command.Positional`，不增加 schema 字段。`Bind` 只接受指向结构体的非空指针，字段使用固定 `command:"参数名"` 标签；普通字段和一层指针字段可绑定 String、Enum、Int、Float 及 Bool，缺失普通字段写类型零值，缺失指针字段为 nil，显式空值及默认值仍保留存在性
9. `Bind` 要求每个 schema 参数恰有一个导出可写字段，`command:"-"` 可显式忽略字段；未导出字段、未知标签、重复绑定、类型不符、多层指针及不可写目标返回含参数名和修复方向的 `InvalidArgument`。绑定不使用 unsafe，也不提供包级全局注册器

Descriptor 校验（冻结）：

1. 进程初始化后 Descriptor 不可变；变更订阅、命令或能力必须重新加载
2. `ID` 非法、与文件名推导值不一致、为空或重复时拒绝加载并清理进程；限定为 ASCII 1—64 字节，拒绝路径分隔符
3. Subscriptions 出现非法主题语法，Commands 路径重复或与框架保留 /golem 冲突时拒绝加载（重复路径 AlreadyExists，保留路径冲突 InvalidArgument）
4. `Mode=Observe` 的订阅不得同时声明同主题 `Mode=Respond`
5. 校验失败的错误类别为 `InvalidArgument`；文件名与 ID 不一致为 `FailedPrecondition`
6. 未知权限、重复订阅/能力/参数、非法能力名或 ContentType、未知枚举、非法默认值、Min > Max 均拒绝加载；能力及 UsesCapabilities 名称采用非空点分段，不能含通配符
7. 声明业务接口必须实际实现相应 handler；缺少可选生命周期视为无操作，不自动声称具备业务能力。同一命令路径重复返回 AlreadyExists

### 5.3 权限名

首期权限标识（字符串常量，写入 Descriptor 与插件配置）：

| 权限 | 覆盖操作 |
| --- | --- |
| `message.send` | 发送、回复、撤回本人消息 |
| `message.read` | 读取消息与下载媒体 |

## 六、事件主题

### 6.1 语法

分段点分语法，例如 `message.text`、`message.image`、`contact.changed`、`room.changed`、`room.member.changed`、`session.expired`、`account.changed`。

1. 支持精确匹配与**末尾整段**通配：`message.*` 匹配 `message.text`、`message.image`，不匹配 `messagex`、`message.text.extra`
2. 不做任意前缀匹配，不做中间通配（`message.*.extra` 非法）
3. 主题是字符串常量，新增主题属于兼容变更，不改握手版本
4. 首期主题清单见 `golem-frame/docs/core接入映射.md` 第 9 章，由 frame 与 core 同步事件映射决定

### 6.2 订阅语义

1. 普通响应链按 priority 升序、同优先级按 PluginID 稳定排序
2. `EventResult.Consumed=true` 才终止普通响应链；`false` 或错误继续后续插件，错误同时记录
3. 命中会话租约的事件只交给持有插件，不进入普通响应链；即使返回 `false`、出错或超时也不改投
4. Observe 订阅收到不可变副本，不受 `Consumed` 和租约影响；队列满时丢弃新投递并计数
5. Observe 回调不能消费事件、不能申请交互会话

## 七、能力契约

能力名即公共约定，不附带版本号，不指定提供插件。首期参数固定为规范 JSON，`CapabilitySpec.InputType = application/json`，不兼容声明必须拒绝加载；同名能力的可路由提供者还必须使用相同 `OutputType`。内联结果上限 256 KiB，超过时使用 `Media` 引用（T26 落实）。

提供者可通过 `CapabilitySpec.MaxInlineSize` 声明更小的内联结果上限；0 使用默认 256 KiB，不得大于默认值。frame 对超过该提供者声明上限的成功结果返回 `ResourceExhausted`。

### 7.1 `text.to.image`

作用：把 UTF-8 文本渲染为图片。**不负责发送消息**。

参数：

| 字段 | 类型 | 必填 | 语义 |
| --- | --- | --- | --- |
| `text` | string | 是 | UTF-8 文本，去空白后不能为空；按原文渲染，不解析 Markdown |
| `font_color` | string | 否 | 前景色，仅 `#RRGGBB`；默认 `#000000` |
| `bg_color` | string | 否 | 背景色，同格式；默认 `#F7F7F7`；必须不透明 |

成功结果：`ContentType = image/png`；小结果 Payload 为 PNG 字节，大结果由 frame 签发可读取的 Image MediaRef（与 Payload 互斥）。T26 媒体流未实现前，超出内联限额返回 ResourceExhausted。

校验规则（调用方必须执行）：

1. 结果非空；内联不超过 256 KiB，引用结果不超过该次调用媒体预算（初始 64 MiB）
2. 前 8 字节为 PNG 签名 `89 50 4E 47 0D 0A 1A 0A`
3. `image.DecodeConfig` 成功，宽高均大于 0、各不超过 8192，像素总数不超过 1600 万；读取与完整解码均有大小、资源和期限限制，PNG 签名和头部检查不能代替完整图片有效性校验
4. 任一校验失败视为渲染无效，按业务降级（帮助发送原文本），不发送图片

失败：

| 情况 | 类别 |
| --- | --- |
| `text` 缺失或去空白后为空 | `InvalidArgument` |
| 颜色格式非法 | `InvalidArgument` |
| 字体等渲染资源缺失 | `FailedPrecondition` |
| 超过内联上限且无法提供媒体引用，或超媒体预算 | `ResourceExhausted` |
| 无可用提供者 | `NotFound` |
| 提供者声明能力却未实现 handler | 加载校验失败；运行时返回 `Unimplemented` 属提供者违约 |

### 7.2 `statistics.query_messages`

作用：按授权群会话、时间范围与成员维度查询历史文本发言，供其他插件分析使用。不暴露提供插件 ID、数据库句柄、数据库行号或存储位置。

以下参数和结果形状是 **T29 设计候选**，不冻结字段名；T01 冻结的是本节后面的有界语义，T29 实现前补齐最终 schema、排序和游标测试。

| 字段 | 类型 | 必填 | 语义 |
| --- | --- | --- | --- |
| `conversation` | string | 是 | 群 username；首期只支持群会话 |
| `actor` | string | 否 | 只取该成员的消息；空表示整群 |
| `since` | string | 否 | RFC3339 时间下限，含边界 |
| `limit` | int | 否 | 默认 100，最大 1000；超过按 1000 处理 |
| `cursor` | string | 否 | 不透明游标，由上次结果原样回传 |

成功结果：`ContentType = application/json`，正文为对象：

```json
{
  "items": [
    {
      "message_id": "1234567890123456789",
      "conversation": "123@chatroom",
      "actor": "wxid_member",
      "created_at": "2026-10-26T09:00:00Z",
      "text": "你好"
    }
  ],
  "next_cursor": ""
}
```

规则：

1. 结果有界：`limit` 上限 1000，且提供者自身总条数预算不得被单次调用突破
2. 只能返回调用方有权访问的会话；越群查询返回 `PermissionDenied`
3. 无数据返回 `items: []`，不是 `NotFound`
4. 后台调用需要 `background.run` 与目标会话白名单共同授权
5. 单次返回最多 1000 条并受 256 KiB 内联预算限制，超过字节预算应提前分页或明确 ResourceExhausted；不得截断单条文本后冒充完整结果
6. 保留旧业务“最近 N 条、页内时间正序”的分析用途；分页需稳定次序和唯一续接键，不重不漏。首/末时间相同的多条记录也必须有确定排序；最终分页方向由 T29 定稿
7. `since` 使用带时区时间、含下界；非法时间、负 limit、无效游标返回 InvalidArgument。旧数据库行号不能冒充微信消息 ID

与旧业务的差异（T29 必须遵守）：

| 旧参数（`Z:/Project-Go/new_golem/plugins/statistics`） | 新参数 | 差异 |
| --- | --- | --- |
| `chatroom` 必填（与 `member` 至少一个） | `conversation` 必填 | 旧版允许只传 `member` 做跨群全局查询；新版不允许跨群无界查询，必须指明会话 |
| `member` | `actor` | 改名，语义相同（该会话内的实际发言者 username） |
| `since`（本地时间 `2006-01-02 15:04:05`） | `since`（RFC3339） | 时间格式改为带时区的 RFC3339，避免跨机器本地时区不一致 |
| `since_id`（增量游标，整数） | `cursor`（不透明字符串） | 不暴露数据库主键；游标由提供者解释 |
| `limit`（`0` 表示不限） | `limit`（默认 100，最大 1000） | 旧版 `0` 可返回整群全量；新版必须有界 |
| — | `next_cursor` | 新增分页续接，旧版没有 |

旧版 `storage.go:267 queryMessages` 只查 `type='文本'`，limit>0 时取数据库 id 倒序的最近记录并反转回时间正序，limit<=0 则无上限；返回 `historyMsg.ID` 是数据库自增行号，**不是**上游消息 ID。T29 必须单独保存真正的业务消息 ID，不能把旧行号转换成 SendReceipt/Message 的 ID。旧版 timestamp 使用本地时间，新结果统一 RFC3339 UTC。上述 JSON 仅用于说明，不要求兼容旧格式。

## 八、结果语义汇总表

| 场景 | 结果 |
| --- | --- |
| 查询分页 | 默认 100，最大 1000；`NextCursor` 空表示结束 |
| 未初始化 | `FailedPrecondition` + `Reason=not initialized`；不隐式回源 |
| 资料不完整 | 正常返回 + `Incomplete` 标记；不得据此授权 |
| 批量部分成功 | 逐项 Value/Error/Outcome 与整体非 nil error；只读刷新 OutcomeNotApplicable |
| 写超时/取消 | 已提交且未知则 `OutcomeUnknown`；提交前拒绝为 Failed；不自动重试 |

| 引用跨账号 | `PermissionDenied` |

## 九、wire 转换与构建隔离

### 9.1 目录职责

| 位置 | 内容 | 可见性 |
| --- | --- | --- |
| `proto/golem/sdk/` | 唯一协议源，按 model/plugin/host/media 分文件，无版本子目录 | 仓库内 |
| `internal/wire/` | 生成代码与双向转换实现 | 仅 SDK 内部 |
| `plugin/`、`message/`、`contact/`、`chatroom/`、`session/`、`capability/`、`config/`、`command/`、`event/` | 插件可见纯业务类型与接口 | 公开 |
| `rpc/` | frame 接入用的公开构造与注册入口 | 公开 |

规则：

1. 插件业务签名只出现业务类型，不出现生成类型
2. frame 通过 `sdk/rpc` 的公开构造与注册入口接线，可导入 SDK 公开业务包，不能导入 `sdk/internal`
3. 生成代码由固定版本工具链生成（`task proto`），不手工修改
4. SDK、插件、frame 非 lib 文件不得 import github.com/golemwx/core；私有协议字段仅允许在 frame/api 的 HTTP DTO/lib 转换内部消费，不进入 SDK、插件或 frame 上层业务

### 9.2 转换位置

1. 业务类型 ↔ wire 类型的转换集中在 `internal/wire/convert*.go`
2. 转换必须显式处理：字段存在性、枚举未知值、`time.Time` ↔ Timestamp、字符串 ID 原样保真、深层切片/映射复制
3. 每次转换都必须有往返测试：`业务 → wire → 业务` 与原值语义相等（按存在性比较，而非 `reflect.DeepEqual` 的零值相等）
4. 不允许通过 Marshal/Unmarshal 私有协议类型假设字段编号相同

### 9.3 大整数与 JSON

1. SDK Proto 和业务类型的消息 ID 均为 `string`；core 的 int64/uint64 仅在 frame/api 适配边界转换，不把私有字段类型复制进 SDK
2. 来自 core SSE 的 `new_id` 等 64 位 JSON 数字必须用 `json.Decoder.UseNumber()` 解析后转字符串，禁止先转 `float64`
3. 来自插件的无效 ID 参数返回 `InvalidArgument`；上游缺失、非正数或溢出是 `Internal`，不截断、不改成成功。SDK string 转换本身不经过整数类型
4. 必填 ID 的空字符串或 "0" 非法；只有契约明确允许缺失的结果（如 OutcomeUnknown 的 SendReceipt）才能保留空，不把非法必填值静默变成缺失

## 十、T02—T08 必测用例清单

以下用例由后续任务实现并归属到具体测试：

### 10.1 字段往返（T06）

1. 每个领域模型取“全部字段有值”样本，往返后逐字段比较
2. 每个模型取“仅必填字段”样本，往返后可选字段仍为缺失而非零值
3. 显式空 `""` 与缺失区分：往返后仍可区分
4. `time.Time` 纳秒精度往返相等、UTC 归一；必填零时间拒绝，可选时间的 nil 保持缺失；越界 Timestamp 拒绝
5. `Message.Mentions`、`ChangedFields` 空切片与 nil 区分

### 10.2 空值与缺失（T06、T07）

1. `Text=*""`（显式空文本）与 `Text=nil`（非文本）区分
2. 在线 Account.Username 为空时返回 Internal；Unlogged/Unknown 状态允许空 username
3. `Conversation.ID` 为空、`Kind=Unknown` 时所有会话相关方法返回 `InvalidArgument`
4. 配置 `Data=[]byte{}` 与 nil 区分

### 10.3 未知枚举（T06）

1. 收到数值 999 的 `MessageKind`：映射为 `MessageKindUnknown`，不 panic，保留 `Text`
2. 收到未知 MemberRole/ContactKind 映射为各自 Unknown，未知 WriteOutcome 映射 OutcomeUnspecified（0），不得当作成功
3. 反向：未知业务枚举编码为 0，不丢失其余字段

### 10.4 超大数值（T06、T07）

1. `new_id = 18446744073709551615`（uint64 上限）往返为同一十进制字符串
2. `new_id = 9007199254740993`（大于 2^53）经 JSON 解析不丢精度
3. SDK string ID 原样往返；frame 拒绝非法插件 ID 参数，拒绝 core 中的非正数/超 uint64 字段（分类见 9.3）
4. `PageRequest.Limit = 100000` 被钳制为 1000；负数返回 InvalidArgument

### 10.5 群发言者解析失败（T12；SDK T06 验证结果往返）

1. 群消息正文没有 `:\n` 前缀：`Actor=nil`、`ActorResolution=ParseFailed`，不把群 username 当 Owner
2. 前缀是群 username 自身：仍标记 `ParseFailed`，不认定为操作者
3. 系统消息（如入群提示）标记 `System`，`Actor=nil`
4. 私聊入站 Actor 是对端，私聊出站 Actor 是账号本人；群出站会话取 receiver，Actor 不冒充群
5. 前缀解析成功但成员不在本地索引：`Actor.Username` 有值，`DisplayName` 缺失，`Resolution=Resolved`
6. Owner 判断在 `Actor=nil` 时恒为 false

### 10.6 部分成功与写结果（T08 传输；T11/T14/T25 业务验证）

1. 批量刷新联系人：3 项中 1 项失败，保留 3 项结果，各项 OutcomeNotApplicable，成功项有 Value 且 Error=nil，失败项非 nil Error，整体 error 非 nil
2. 发送超时：`OutcomeUnknown`，`RevokeRef=nil`，不自动重发
3. 发送响应无完整 MessageID、缺少必须的逐项 code 或回显会话不符：Internal + OutcomeUnknown，不返回空成功、不重发
4. 撤回引用跨账号使用：`PermissionDenied`
5. 撤回引用在实例重启后使用：`FailedPrecondition`

### 10.7 握手与兼容（T07）

1. cookie 不匹配、ProtocolVersion 不匹配：握手阶段明确失败，无遗留进程
2. 新增可选 Proto 字段：旧端忽略未知字段，握手配置不变
3. 新增能力名、新增主题：不提高 ProtocolVersion
4. 删除字段保留编号与名称；不重排编号
