# 公共契约

## 1. 状态与版本

本文件冻结 GOLEM-39 / R02 的公共 Go 模型和 wire 契约，并记录 GOLEM-40 / R03 已实现的
进程运行时边界，设计依据为 2026-11-06 冻结方案
（`updatedAt=2026-11-06T05:10:26Z`）第六、七、八、十二、十四、十六节。

仓库基线：`7475c5f89ebe465d9aadda284a6b5c09d0a231a5`。R02 最终提交及验证结果记录在
GOLEM-39 正文，R03 最终提交及验证结果记录在 GOLEM-40 正文；下游必须使用这些提交或
包含同一契约的后续修订，不能引用旧 T 系列。

R03 已提供真实插件进程、Describe/Initialize、生命周期、Host 反向连接和单实例锁。
命令、配置、数据目录和日志桥接仍未实现，必须返回 `CategoryUnimplemented`，不能返回
空成功；具体实现分工见第 13 节。

## 2. 依赖与 wire 边界

- Proto 是唯一 wire 来源：`proto/golem/sdk/*.proto`
- 生成代码只位于 `internal/wire`，不进入公共签名
- SDK 不导入 `github.com/golemwx/core`
- 公开模型不使用 core DTO、core 配置、会话、设备或 CDN 私有类型
- 消息结构化 Data 使用 Proto `oneof`，不使用 `Any`
- 不定义媒体、转发或撤回业务 token
- 不定义 tenant、账号 epoch、实例代次、后台 token、配置 revision/active/apply 字段
- 不维护旧协议兼容分支、deprecated alias 或双字段迁移层

R03 直接依赖 `google.golang.org/grpc`、`google.golang.org/protobuf`、
`github.com/hashicorp/go-plugin`、`github.com/hashicorp/go-hclog` 和
`github.com/gofrs/flock`。hclog 当前只作为 go-plugin 的空日志器依赖，结构化桥接由
R07 实现。

## 3. 消息模型

包：`github.com/golemwx/sdk/message`

```go
type Message struct {
	ID        uint64
	Type      Type
	Sender    contact.Contact
	Receiver  contact.Contact
	Member    *chatroom.Member
	Content   string
	Raw       []byte
	Timestamp time.Time
	Data      Data
}
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `ID` | frame 归一后的权威消息 ID；优先 core `new_id`，缺失时使用可无符号表达的 `id`，禁止经 float64 |
| `Type` | `TypeUnknown` 或八类已支持类型 |
| `Sender` / `Receiver` | 保留原始会话方向；群消息的群身份在 Sender/Receiver，实际发言者在 Member |
| `Member` | 仅群消息实际发言者；无法确定时为 nil，不能用群身份代替 |
| `Content` | 始终保留的稳定正文字符串或摘要 |
| `Raw` | frame 从已识别同步输入建立的原始副本；插件视为只读，不要求 core 透传未知命令 |
| `Timestamp` | 消息创建时间，必须非零 |
| `Data` | 已解析的八类类型化数据；解析失败或未知类型时为 nil |

`Data` 是封闭接口，插件不能实现。八类实现都必须使用指针：

```go
type Data interface{ isMessageData() }

type Text struct{}
type Image struct { Media; Width, Height uint32 }
type Voice struct { Media; Duration time.Duration; Format string }
type Video struct {
	Media
	Duration      time.Duration
	ThumbnailURL  string
	ThumbnailKey  string
	ThumbnailSize uint64
	NewMD5        string
}
type Emoji struct { MD5, URL string; Size uint64 }
type Location struct { X, Y float64; Label, POIName string }
type App struct { Type uint32; Title, Description, URL string }
type File struct { Media; Name, Extension, AppID, AttachID string }
```

媒体公共字段：

```go
type Media struct {
	FileID string
	MD5    string
	Key    string
	URL    string
	Size   uint64
}
```

这些是已识别同步数据中的真实字段，不是宿主签发的业务引用。`Message` 提供
`Text()`、`Image()`、`Voice()`、`Video()`、`Emoji()`、`Location()`、`App()`、`File()`
类型断言便捷方法；类型不符时返回 nil。

### 3.1 Content 语义

| 类型 | Content |
| --- | --- |
| 文本 | 去除群成员前缀后的正文 |
| 图片 | `[宽 x 高] 大小` |
| 语音 | `[时长] 大小` |
| 视频 | `[时长] 大小` |
| 表情 | MD5；缺失时使用可读描述 |
| 位置 | POI 名称；缺失时使用地址标签 |
| 应用 | 标题；缺失时使用描述或类型摘要 |
| 文件 | 文件名；缺失时使用类型和大小摘要 |
| 未知 | 原始正文可读部分，不能简单留空 |

解析失败时：

1. `Content` 保留进入 parser 前的原始正文
2. `Raw` 保留 frame 已收到的识别输入副本
3. `Data` 为 nil
4. `Type` 和 `Timestamp` 仍按已知字段填写

### 3.2 发送结果与撤回

```go
type SendResult struct {
	ID         uint64
	NewID      uint64
	ClientID   string
	Sender     contact.Contact
	Receiver   contact.Contact
	Type       Type
	CreatedAt  *time.Time
	ServerTime *time.Time
	Outcome    sdk.WriteOutcome
}
```

`ClientID` 必须保留上游文本形态：文本回执可能是数字，媒体回执可能是字符串。文本也可
直接存为十进制字符串，不丢前导形式和内容。视频回执可能没有 `CreatedAt`，SDK/适配层
不得编造。

`Revocable()` 表示“当前 core 撤回入口可表达”：

- 非 nil 结果
- 非零 `NewID`
- 非空 `Receiver.Username`
- `CreatedAt` 非 nil、非零且在 Proto Timestamp 可表达范围内
- `Outcome == OutcomeSucceeded`
- `ClientID` 可解析为非零 uint64

不满足时返回 false。Host 适配层对不可表达参数返回 `FailedPrecondition`，不强转媒体字符串
ID、不填假时间、不自动重试。

### 3.3 消息 Host 能力

```go
type Client interface {
	SendText(ctx context.Context, target, text string, mentions []string) (*SendResult, error)
	SendApp(ctx context.Context, target string, app App) (*SendResult, error)
	SendMedia(ctx context.Context, target string, upload Upload) (*SendResult, error)
	Forward(ctx context.Context, target string, source Message) (*SendResult, error)
	Revoke(ctx context.Context, sent SendResult) error
	Download(ctx context.Context, source Message) (io.ReadCloser, error)
}

type Upload struct {
	Type   Type
	Name   string
	Size   int64
	Reader io.Reader
	Voice  *VoiceUpload
}

type VoiceUpload struct {
	Duration time.Duration
	Format   string
}
```

`Size` 为 `-1` 表示未知；其他负数无效。声明大小必须与 Reader 实际字节数一致。插件拥有
Reader 的关闭责任。媒体发送和下载使用流，不把完整媒体内联进一元消息或事件。

下载、转发和撤回直接接收完整公开值，不先换取 token，也不要求 frame 保存原消息。

### 4.2 Selector

```go
type Selector string
func ParseSelector(value string) (Selector, error)
func (s Selector) Split() (SelectorMode, string, error)
func (s Selector) MarshalText() ([]byte, error)
func (s *Selector) UnmarshalText([]byte) error
```

| 写法 | 匹配 |
| --- | --- |
| `wxid_xxxx` | username 完整匹配 |
| `username::wxid_xxxx` | username 完整匹配 |
| `nickname::小明` | nickname 完整匹配 |
| `remark::owner` | remark 完整匹配 |

以第一个 `::` 分割。空选择器、空检索值、未知前缀返回 `InvalidArgument`。无结果返回
`NotFound`。同名多结果由 frame 按 username 字典序取第一项，不返回歧义错误。

配置和命令使用同一 Selector；文件保留用户原始写法，运行态使用解析结果。owner 解析成功
后固定 username，昵称/备注变化不能静默换管理员。

## 5. 事件与订阅

包：`github.com/golemwx/sdk/event`

```go
type Topic string

const (
	Message  Topic = "message"
	Contact  Topic = "contact"
	Chatroom Topic = "chatroom"
	Member   Topic = "member"
	Account  Topic = "account"
)

type Mode uint8

const (
	ModeUnknown Mode = iota
	Observe
	Consume
)

type Subscription struct {
	Topic    Topic
	Mode     Mode
	Priority int
}

type Event struct {
	Topic      Topic
	Message    *message.Message
	Contact    *contact.Contact
	Chatroom   *chatroom.Chatroom
	Member     *chatroom.Member
	OccurredAt time.Time
}

type Result struct {
	Consumed bool
}
```

规则：

- 事件是一次函数调用输入，不持久化、不重放、不带 tenant/账号 epoch/序号
- 同一插件可对不同主题声明不同模式，但同一主题不能同时 Observe 和 Consume
- 消费者 Priority 越小越先执行；同值按插件 ID 稳定排序
- 观察者返回值被忽略
- 消费者 `Consumed=true` 时是否终止后续链由 frame 的 `stop_on_consume` 策略决定
- 已消费、命令或租约事件仍投递给匹配观察者
- 租约持有者不消费时不回落到普通消费链
- 上游错误默认记录并继续；不算消费
- `Account` 主题不重复携带账号快照；处理器通过 `Host.Account.Current` 读取当前账号

| --- | --- |

## 7. 配置契约

包：`github.com/golemwx/sdk/plugin`

```go
type Status uint8

const (
	StatusUnknown Status = iota
	StatusReady
	StatusPending
	StatusApplyFailed
)

type Config[T any] struct { /* private */ }

func NewConfig[T any](defaults T) *Config[T]
func (c *Config[T]) Snapshot() T
func (c *Config[T]) Status() Status
func (c *Config[T]) Update(ctx context.Context, mutate func(*T) error) error
func (c *Config[T]) Save(ctx context.Context, candidate T) error
func (c *Config[T]) SetConfig(ctx context.Context, toml []byte) error

type ConfigChangeHandler[T any] interface {
	OnConfigChanged(ctx context.Context, previous, next T) error
}

type ConfigClient interface {
	Read(ctx context.Context) ([]byte, error)
	Save(ctx context.Context, config []byte) error
}

type ConfigReceiver interface {
	SetConfig(ctx context.Context, config []byte) error
}
```

状态：

- `StatusReady`：R02 构造默认值可读；R05 中表示宿主配置已通过校验并发布
- `StatusPending`：首次生成的零值配置不合法，等待 owner 修复
- `StatusApplyFailed`：配置已持久化，但业务资源应用失败

R02 行为：

- `NewConfig` 保存默认值
- `Snapshot` 返回构造值
- `Update`、`Save`、`SetConfig` 返回 `CategoryUnimplemented`
- 不读取文件、不等待 ACK、不触发回调、不创建目录

R05 行为：

- Describe 上报默认对象；无自定义默认时上报 T 零值
- 已有配置优先，不用新默认覆盖
- 严格 TOML，拒绝未知字段
- validator/v10 和业务校验
- Snapshot/Update 隔离 map、slice、指针
- 更新锁串行 Update/Save；保存失败不发布候选值
- 落盘成功但 ACK 丢失时读取当前文件对齐，不重复执行修改回调
- 发布后调用可选 OnConfigChanged；回调失败报告“已保存，应用失败”
- 不使用 revision 实现并发控制

## 8. 数据目录契约

```go
type Data interface {
	Open(name string, flag int, perm fs.FileMode) (*os.File, error)
	ReadFile(name string) ([]byte, error)
	WriteFile(name string, data []byte, perm fs.FileMode) error
	Remove(name string) error
}
```

规则：

- 文件名必须是插件根目录内的相对路径
- 拒绝绝对路径、盘符、`..` 和符号链接逃逸
- 只读访问不存在目录返回 `fs.ErrNotExist`
- `Open` 带创建/写标志或 `WriteFile` 才创建目录
- 不接收 plugin ID，不允许调用方改变根目录
- 不提供消息、事件、媒体或配置的隐式持久化
- 无文件 I/O 的插件不产生 `plugins/data/<id>` 目录

R06 实现上述行为；R03 仍只冻结接口并返回 `Unimplemented`。

### 9.3 Base 与 Runtime

```go
type Base struct {
	Host *Host
	// 启用期 context 为私有字段，通过 Context() 读取
}

func NewBase() *Base
func (b *Base) Context() context.Context

type InitializeOptions struct {
	Host    *Host
	Config  []byte
	DataDir string
}

type Runtime interface {
	Describe(ctx context.Context) (*Descriptor, error)
	Initialize(ctx context.Context, options InitializeOptions) error
	Load(ctx context.Context) error
	Start(ctx context.Context) error
	Stop(ctx context.Context) error
	Unload(ctx context.Context) error
	ValidateConfig(ctx context.Context, config []byte) error
	SetConfig(ctx context.Context, config []byte) error
	HandleEvent(ctx context.Context, value event.Event) (event.Result, error)
	HandleCommand(ctx context.Context, invocation command.Invocation) error
	HandleCapability(ctx context.Context, request capability.Request) (capability.Result, error)
}
```

`NewBase` 初始不绑定 Host，`Context()` 返回 nil。R03 在 Initialize 成功后发布当前实例
唯一的 Host；Start 成功前发布新的启用周期 context。Host 字段在 Stop/Unload 后保留，但
远程能力会明确失败。`InitializeOptions.Config` 与 `DataDir` 由 R05/R06 消费；R03 只校验
输入非空，不加载配置，也不创建数据目录。

生命周期语义：

- 同一 Runtime 只能 Initialize 一次；Load 后才能 Start
- Stop 先关闭业务准入和 Host 访问，再取消启用周期并调用可选 OnStop
- Stop 等待真实 handler 返回，不接受调用方 context 取消作为结束依据
- Stop 后可以再次 Start 建立新周期；断连会永久让当前实例失效，不能通过 Start 恢复
- Unload 在需要时先完成停用排空，再调用可选 OnUnload 并永久关闭实例
- handler panic 被转换为脱敏的 `Internal`，不泄漏 panic 内容

### 9.4 进程入口、实例锁与 frame 客户端

```go
func Serve(plugin Plugin)

type ClientOptions struct {
	Command      *exec.Cmd
	PluginID     string
	Host         *Host
	ConfigClient ConfigClient
	Config       []byte
	DataRoot     string
	StartTimeout time.Duration
}

func Start(ctx context.Context, options ClientOptions) (*Client, error)

func (c *Client) Descriptor() Descriptor
func (c *Client) Load(ctx context.Context) error
func (c *Client) Start(ctx context.Context) error
func (c *Client) Stop(ctx context.Context) error
func (c *Client) Unload(ctx context.Context) error
func (c *Client) Close() error
func (c *Client) Exited() bool
func (c *Client) PID() string
func (c *Client) ValidateConfig(ctx context.Context, config []byte) error
func (c *Client) SetConfig(ctx context.Context, config []byte) error

```

`Serve` 在 go-plugin 握手和任何业务生命周期回调前取得
`<install>/run/plugin-<id>.lock` 的 OS 排他锁；进程退出后 OS 自动释放，锁文件本身不删除。
`GOLEM_PLUGIN_INSTALL_DIR` 可覆盖安装根目录，`GOLEM_PLUGIN_LOCK_PATH` 可覆盖完整锁路径。

`Start` 启动一个真实子进程，在同一进程内依次完成协议握手、Describe、反向 Host 注册和
Initialize，不会启动第二个校验进程。`ClientOptions.Command` 必须尚未启动，`Host` 不得为
nil。`Client.Unload` 会尝试结束进程，并仅在 `Client.Exited()` 为 true 时成功返回；
`Client.Close` 同样阻塞到 go-plugin 确认退出。R10 退出确认协议见
[插件通信](插件通信.md)。

握手常量和 `HandshakeConfig()` 只用于 frame 创建匹配的 go-plugin 客户端，不承担业务授权。
Proto 不兼容变更时提高 `ProtocolVersion`。

### 9.5 日志字段

```go
const (
	LogFieldPluginID   = "plugin_id"
	LogFieldPluginName = "plugin_name"
)
```

插件直接使用 `log/slog`。宿主最终日志会覆盖或注入这两个可信字段；插件不能在属性中冒充。
R07 负责桥接。stdout 只用于插件握手。

## 10. 能力调用

包：`github.com/golemwx/sdk/capability`

```go
const MaxInlineSize = 256 << 10

type Spec struct {
	Name          string
	Description   string
	InputType     string
	OutputType    string
	MaxInlineSize int
}

type Request struct {
	Name        string
	ContentType string
	Payload     []byte
}

type Result struct {
	ContentType string
	Payload     []byte
}

type Client interface {
	Call(ctx context.Context, request Request) (*Result, error)
}
```

请求/结果只在内存中路由，不保存调用记录，不建立媒体仓库。单次内联大小不得超过
`MaxInlineSize`。`Spec.MaxInlineSize=0` 表示公共上限，其他值必须落在
`(0, MaxInlineSize]`。大媒体由提供者直接通过 `message.Client` 发送。

## 11. 错误与写结果

包：`github.com/golemwx/sdk`

```go
type Error struct {
	Category   Category
	Operation  string
	Outcome    WriteOutcome
	Reason     string
	RetryAfter time.Duration
}

func NewError(category Category, operation, reason string) *Error
```

`NewError` 的 Outcome 固定为 `OutcomeNotApplicable`；写操作调用方必须显式设置
`OutcomeSucceeded`、`OutcomeFailed` 或 `OutcomeUnknown`。

| Category | 使用场景 |
| --- | --- |
| `InvalidArgument` | 命令、配置、选择器、消息或能力参数无效 |
| `PermissionDenied` | 非 owner、连接身份、资源范围或策略不允许 |
| `NotFound` | 联系人、群、命令、能力或资源不存在 |
| `FailedPrecondition` | 账号/插件状态不允许，或撤回参数不可表达 |
| `ResourceExhausted` | 队列、并发、载荷大小超限 |
| `Unimplemented` | 契约已定义但当前任务未实现 |
| `DeadlineExceeded` | context 期限到 |
| `Canceled` | context 取消 |
| `Unavailable` | core、插件进程或连接暂不可用 |
| `Internal` | 内部约束或上游响应损坏 |

规则：

- 调用方只按 Category 和 Outcome 分支，不匹配 Reason
- 错误返回一次、记录一次，不重复包裹
- 有副作用的请求已提交但响应丢失、超时或取消时使用 `OutcomeUnknown`
- `OutcomeUnknown` 不自动重试，避免重复发送或重复写入
- 未实现路径返回 `Unimplemented`，不能返回 nil error 或空结果
- 跨进程 Reason 必须脱敏，不含路径、Cookie、密钥、完整正文或握手输出

## 12. Proto 服务

### 12.1 插件方向

`PluginControlService`：

| 方法 | 说明 |
| --- | --- |
| `Describe` | 元数据、订阅、命令树、能力、默认配置 |
| `Initialize` | 唯一 Host broker、配置、数据根路径 |
| `Load` / `Start` / `Stop` / `Unload` | 生命周期 |
| `ValidateConfig` | 校验候选配置，不修改状态 |
| `SetConfig` | 校验、发布和变更通知 |

`PluginBusinessService`：

| 方法 | 说明 |
| --- | --- |
| `HandleEvent` | 瞬时事件 |
| `HandleCommand` | tokens、原始文本、消息、owner 信息 |
| `HandleCapability` | 跨插件能力调用 |

### 12.2 宿主方向

| 服务 | 方法 |
| --- | --- |
| `HostAccountService` | `Current` |
| `HostMessagesService` | `SendText`、`SendApp`、`SendMedia`、`Forward`、`Revoke`、`Download` |
| `HostContactsService` | `Find` |
| `HostChatroomsService` | `Get`、`Members` |
| `HostSessionsService` | `Acquire`、`Renew`、`Release` |
| `HostCallerService` | `Call` |
| `HostConfigService` | `Read`、`Save` |

Proto 不含媒体引用服务、core 调用服务、后台 token、配置 revision/resume/drain 双状态协议。
`SendMedia` 是客户端流，首包必须是元数据且只能出现一次，后续只能发送字节；最终一元响应
携带结构化的 `Error`。`Download` 是服务端流，每个成功包在 `DownloadResponse.data` 中
返回字节，终止业务错误在最后一个 `DownloadResponse.error` 中返回；传输中断使用 gRPC
status，不伪装成正常 EOF。

所有一元 RPC 的业务失败都写入响应自己的 `error` 字段并保持 gRPC status 成功；只有连接、
帧格式或传输层失败才使用非 OK 的 gRPC status。调用方不得把空 `error` 且缺失业务结果的
响应当作成功。

### 12.3 手写/生成契约测试

`internal/wire/contract_test.go` 和 `contract_extra_test.go` 检查：

- 八类 Data 真实 Proto 往返保留 Content、Raw、Type、Timestamp 和参与者
- 解析失败保留 Content/Raw，Data 为 nil
- Data 与 Type 不一致被拒绝
- 未知枚举归一为公开零值
- BytesValue 区分 nil 与显式空载荷
- SendResult 保留数字/字符串 ClientID、缺失时间和撤回字段
- 命令 schema 保留 Short、Positional、Map、Enum
- Descriptor 保留订阅、能力和默认配置
- 整型越界和非法时长返回 InvalidArgument
- 下载服务端流保留 data/error 的 oneof 形状
- 生成 `oneof` 八分支、服务方法集合和无旧字段

## 14. 最小可运行示例

```go
package main

import (
	"context"

	"github.com/golemwx/sdk/event"
	"github.com/golemwx/sdk/plugin"
)

type Plugin struct {
	*plugin.Base
}

func New() *Plugin {
	return &Plugin{Base: plugin.NewBase()}
}

func (*Plugin) Metadata() plugin.Metadata {
	return plugin.Metadata{ID: "fixture", Name: "示例"}
}

func (*Plugin) Subscriptions() []event.Subscription {
	return []event.Subscription{{Topic: event.Message, Mode: event.Consume}}
}

func (*Plugin) OnEvent(ctx context.Context, value event.Event) (event.Result, error) {
	if value.Message == nil {
		return event.Result{}, nil
	}
	// msg.Content 对八类消息都可用；msg.Data 可为 nil（解析失败）。
	return event.Result{Consumed: false}, nil
}

func main() {
	plugin.Serve(New())
}
```

示例使用 R03 进程入口；没有配置保存、数据目录或日志桥接代码。

## 15. 兼容与修订

- R02 是破坏性重建，不保留旧 `CommandSpec`、`MediaRef`、`ForwardRef`、`RevokeRef`、
  token、revision、core API 客户端或旧 RPC 包
- 字段或服务语义变化必须同步 Proto、转换、契约测试、文档和 GOLEM-39 登记
- 下游仓库按同一 R02 修订实现；发现设计冲突先登记，不自行增加兼容别名
- 最终整体方案符合性由 R25 独立核对
