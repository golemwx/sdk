## T26 媒体上传流审阅（2026-10-29）

### 实现与修复

- `Messages.SendMedia` 使用客户端流发送首包元数据和最多 256 KiB 的字节块，不序列化
  Reader，也不接受插件本地路径；调用方继续拥有 Reader 的关闭责任
- 图片、语音、视频、文件使用 64 MiB 初始上限，表情遵守 core 已明确的 10 MiB 上限；
  声明长度、实际累计量、空流、短读、多读和长期无进展 Reader 均有明确检查
- 宿主流拦截器在可信边界预读并回放首包，沿用一元 RPC 的实例凭据、父期限、取消和
  frame 授权上下文；媒体流不能绕过方法及资源授权
- 宿主用 `io.Pipe` 把 gRPC 分块交给 frame，消费速度直接反压接收，不按总媒体大小建立
  SDK 内存缓冲；成功、错误、取消和提前返回都关闭 pipe
- 语音只接受精确毫秒且不超过 int32 毫秒的时长及公共编码；文件名拒绝目录、盘符和控制
  字符。媒体引用、下载和撤回继续保持 T27 的 `Unimplemented` 边界

### 审阅结论

复审补充了异常 Reader 返回计数检查、读取间 context 检查和调用方 Reader 所有权测试；
没有引入 core 依赖、临时路径、URL 直通或媒体全量缓存。Proto 字段和唯一协议版本均未
改变，现有生成文件继续由固定 `task proto` 链核对。

## T27 下载、撤回、转发与图片帮助契约审阅（2026-10-29）

### 公共契约

- 新增受限 `ForwardRef`，并为 `Message` 补充可空转发引用；`MediaRef`、`RevokeRef`、
  `ForwardRef` 都只携带不透明 token、期限和必要公开元数据，不公开宿主路径、原始 XML、
  CDN 标识、密钥或私有协议对象
- `SendReceipt` 统一返回 `MessageID`、`Outcome` 与可用时的 `RevokeRef`；未知写入结果不允许
  携带可重复操作的撤回引用，调用方不得自动重试或切换提供者
- `MessagesClient` 增加有界 `StoreMedia`、`Download`、`Revoke`、`Forward` 以及结构化链接、
  位置和名片入口；不提供任意原始应用消息或远程 URL 下载入口
- 下载流在返回调用方前预取首块，并持续核对分块、总量和声明长度；取消或关闭都会释放
  底层流。暂存与发送沿用 T26 的文件名、类型、分块和总量边界

### 审阅与 T26 衔接

- Proto 只增加显式业务 RPC 和结构化字段，生成代码由固定链更新；手写转换同时校验空引用、
  UTC 期限、引用种类、位置范围、有限缩放值和 HTTPS/HTTP 链接
- 服务端区分暂存输入错误与已经开始消费后的协议错误，避免把未发生的写副作用标为未知；
  下载是只读操作，流错误不伪装成发送结果
- T26 未闭环的大能力结果媒体由 T27 的 `StoreMedia` 接入：提供者在授权能力执行中暂存输出，
  frame 校验后向实际调用方重新签发引用，提供者 token 不跨实例直接传递
- SDK 保持不依赖 core；frame 的账号、实例、调用范围、会话绑定和重启失效由 frame 私有引用表
  负责，SDK 不解析 token，也不允许插件补造撤回或转发参数

### 验证边界

- 使用 `GOWORK=off GOFLAGS=` 执行全量测试、vet 和 build；媒体与消息专项执行多轮 shuffle
- 固定 Taskfile 生成链执行格式化、lint、远程生成器、重复生成字节一致性和 wire 测试
- 本机无 GCC，按任务要求不执行 race；不访问真实微信、外部模型、core/data，不执行发布或 push
- frame 两种 adapter 的具体支持类型、引用错误映射和图片帮助发送由 frame 仓 T27 验收；
  不能一致支持的类型必须返回 `Unimplemented` 并在执行清单登记
