# 开发指南

## 模块边界

```text
plugins → sdk
frame   → sdk
frame adapters/lib → core
core    → 标准库和 core 自身依赖
```

SDK 不导入 `github.com/golemwx/core`。R03 直接依赖 gRPC、Protobuf、go-plugin、
hclog 和跨平台文件锁；R04 增加 `alecthomas/kong`、`go-playground/validator/v10` 和
`robfig/cron/v3`；R05 增加 `pelletier/go-toml/v2` 用于严格 TOML 编解码。hclog 目前只
作为 go-plugin 日志通道和插件侧 slog JSON 输出，宿主侧只使用标准库 `log/slog`。所有依赖
都必须由 `go mod tidy -diff` 保持确定。

公共包：

- `message`、`contact`、`chatroom`、`session`
- `event`、`command`、`capability`
- `plugin`

传输包：

- `proto/golem/sdk`：唯一 Proto 源
- `internal/wire`：生成代码与公开模型转换

`internal/wire` 不是公共 API。frame 和插件不得导入生成类型；需要跨进程时使用
Proto 服务，需要给插件使用时使用公开领域类型。

## 生成链

```powershell
task proto
```

固定工具版本：

```text
Buf                 1.75.0
protoc-gen-go       1.36.12
protoc-gen-go-grpc  1.6.2
```

生成链依次执行：

1. `buf format -w`
2. `buf format --diff --exit-code`
3. `buf lint`
4. `buf generate`
5. 临时目录重复生成并逐字节比对全部 `.pb.go`
6. `go test -count=1 ./internal/wire`

不要手工编辑 `internal/wire/*.pb.go`。修改 wire 形状时先改 `proto/`，再运行固定链。

## 正式检查

```powershell
task deps:check
task test
task lint
task build
task ci
```

Taskfile 在任务级设置 `GOWORK=off`、`GOFLAGS=` 和 `CGO_ENABLED=0`，避免上级
`go.work` 掩盖独立模块问题。`task test:race` 单独设置 `CGO_ENABLED=1`，需要 C
编译器；没有 GCC 时只能记录未运行。

## 测试要求

- 消息契约必须经过真实 `proto.Marshal`/`proto.Unmarshal`，不能只比较 Go 结构体。
- 八类 Data、Content、Raw、未知枚举、解析失败正文和 SendResult 撤回字段分别有测试。
- 手写转换的整型范围、时长、nil/空包装和 `oneof` 分支必须有边界测试。
- 使用 `GOWORK=off` 检查 SDK 自身依赖图，并搜索 `golemwx/core`。
- 插件生命周期测试必须包含真实子进程，覆盖锁竞争、启动失败、停止、卸载和重载。
- 忽略取消的 handler 必须等待其真实返回；不能把调用方超时当作 handler 已结束。
- frame 侧协议测试必须检查 `Client.Exited()`，未确认退出前不得启动同 ID 替代进程。
- 不执行真实微信、CDN、账号登录、外部模型或未授权数据目录。
- 任何未运行项都要在验收记录中写明原因，不能改写成通过。

契约字段变化必须同步更新 Proto、转换、契约测试和[公共契约](公共契约.md)；
R02 冻结后跨仓改动先登记冲突，不在下游仓库自行发明字段。
