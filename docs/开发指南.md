# 开发指南

## 模块边界

- `plugin`：插件描述、生命周期、业务接口和自动绑定 Host 的 Base
- `event`、`command`、`capability`：事件、命令和跨插件能力契约
- `message`、`contact`、`chatroom`、`session`、`config`：领域模型和类型化 Host 客户端
- `rpc`：共享配对配置、真实插件启动、控制 RPC 和反向 Host 服务
- `internal/wire`：Proto 生成的传输类型和转换，不是公共 API
- `proto/golem/sdk`：唯一 Proto 源

插件业务签名只能使用公开领域类型。frame 通过 `sdk/rpc` 接线，不直接导入
`internal/wire`；SDK 不依赖 `github.com/golemwx/core`。

## 生成链

```powershell
task proto
```

固定工具版本：

```text
Buf                        1.75.0
protoc-gen-go             1.36.12
protoc-gen-go-grpc        1.6.2
```

生成链依次执行格式检查、lint、生成、临时目录重复生成和 wire 测试。生成文件以文件头为
准，不手工编辑；新增兼容 Proto 字段必须保持默认行为，不随意修改配对协议版本。

## 正式检查

```powershell
task deps:check
task test
task lint
task build
task ci
```

所有正式命令显式设置 `GOWORK=off GOFLAGS=`。`task ci` 依次执行生成链、依赖检查、
测试、vet 和正式构建。正式构建使用 `CGO_ENABLED=0`；race 是单独的
`task test:race`，需要 CGO 和 C 编译器，不能在无 GCC 环境伪造通过。

## 版本与兼容

配对配置由 SDK 唯一定义：

```text
ProtocolVersion=1
MagicCookieKey=GOLEM_PLUGIN_MAGIC_COOKIE
MagicCookieValue=golem-sdk-grpc
PluginSet=golem
```

普通发布和兼容的 Proto 新增字段保持这些值不变。只有不兼容的通信或业务语义变更才提高
唯一协议版本。插件、frame 和发布二进制应使用同一个可获取 SDK 修订；不要把本地 replace
带入发布 `go.mod`。

## 测试要求

- 涉及并发、取消、执行结束、媒体流或越权检查时补充明确同步和可控时钟测试。
- 不使用任意 sleep 猜测执行顺序。
- 生成后先核对预期差异，再运行 wire 和全量测试。
- 无法执行 race 时记录未验证项及原因，不写成通过。

详细契约见[公共契约](公共契约.md)和[插件通信](插件通信.md)。
