# 宿主能力与安全

## 小型 Host

插件只保存一个实例绑定：

```go
type Host struct {
	Account  AccountClient
	Messages message.Client
	Contacts contact.Client
	Rooms    chatroom.Client
	Sessions session.Client
	Caller   capability.Client
	Data     Data
}
```

不存在的字段包括 core 客户端、插件 ID、tenant、账号 epoch、后台 token、配置 revision
和业务媒体引用。`NewHost` 只做显式注入，便于 frame 测试和 R03 运行时绑定。

所有 I/O 方法第一个参数是 `context.Context`。调用者身份来自当前插件连接，不从业务参数
自报。R03 在 Initialize 时绑定连接；Start 只允许当前启用周期访问，Stop 立即关闭准入并
取消启用周期，反向连接断开后实例永久失效。

| 能力 | 方法 |
| --- | --- |
| 账号 | `Current(ctx)` |
| 消息 | `SendText`、`SendApp`、`SendMedia`、`Forward`、`Revoke`、`Download` |
| 联系人 | `Find(ctx, selector)` |
| 群 | `Get(ctx, username)`、`Members(ctx, username)` |
| 租约 | `Acquire`、`Renew`、`Release` |
| 能力调用 | `Call(ctx, request)` |
| 数据 | `Open`、`ReadFile`、`WriteFile`、`Remove` |

## 消息能力

- `SendText` 接收目标 username、正文和 username 列表
- `SendApp` 接收结构化 `message.App`，不接收任意 core XML
- `SendMedia` 接收流式 `message.Upload`；插件拥有 Reader 的关闭责任
- `Forward` 接收完整源 `message.Message`
- `Revoke` 接收完整 `message.SendResult`
- `Download` 接收完整 `message.Message`

`SendResult` 保留真实 `ID`、`NewID`、字符串 `ClientID`、发送方、接收方、类型、可选
`CreatedAt`/`ServerTime` 和写结果。当前 core 撤回协议只能表达数值 ClientID；因此
`Revocable()` 仅在成功结果、非零 NewID、非空接收方、有效创建时间和可解析 uint64
ClientID 同时存在时为 true。缺失字段时 Host 适配层返回 `FailedPrecondition`，不得强转
或编造时间。

媒体数据包含真实 FileID、MD5、Key、URL 和大小，因为它们来自已识别的同步输入，不是宿主
签发的引用。插件可以直接用这些字段请求下载或转发；frame 不为消息建立业务 token 表或
媒体仓库。

## 联系人选择器

`contact.Selector` 按完整值匹配，不做模糊查询：

| 写法 | 策略 |
| --- | --- |
| `wxid_fixture` | 唯一 username |
| `username::wxid_fixture` | 唯一 username |
| `nickname::小明` | nickname 精确匹配 |
| `remark::owner` | remark 精确匹配 |

以第一个 `::` 分割。空值、`::value`、未知前缀和 `prefix::` 均返回 `InvalidArgument`；
无匹配返回 `NotFound`。同名结果由 frame 按 username 字典序稳定取第一项。owner 解析后应
固定 username，昵称或备注变化不能静默更换管理员。

## 租约与能力

`session.Client.Acquire` 申请联系人或整群的事件消费租约，`Renew` 和 `Release` 只能操作
当前插件持有的租约。初始 TTL、续期范围和过期语义由 frame 落实；R03 仍只冻结签名与
Topic 列表。租约只作用于消费者，观察者仍独立投递。

`capability.Client.Call` 只在内存中按能力名路由。请求和结果使用有界内联字节，单次上限
`capability.MaxInlineSize = 256 KiB`。大媒体不进入能力载荷；提供者应通过 Host 直接发送，
等待后续流式能力契约时不得引入宿主媒体 token。

`capability.Spec.MaxInlineSize` 为 0 表示使用公共上限，其他值必须在
`0 < size <= MaxInlineSize` 范围内；插件侧转换会拒绝负数和超上限值，frame 在
Describe 校验中必须再次拒绝非法值。

## 配置

`plugin.Config[T]` 冻结以下签名：

- `NewConfig(defaults T)`
- `Snapshot() T`
- `Status() Status`
- `Update(ctx, func(*T) error) error`
- `Save(ctx, T) error`
- `SetConfig(ctx, []byte) error`
- 可选 `ConfigChangeHandler[T].OnConfigChanged(ctx, previous, next)`

`plugin.ConfigClient` 提供 `Read(ctx)` 和 `Save(ctx, []byte)`；
`plugin.ConfigReceiver` 提供 `SetConfig(ctx, []byte)`。没有 revision、active revision 或
apply status。

R05 已实现严格 TOML、未知字段拒绝、标签和业务校验、默认值上报、深拷贝、保存、
ACK 丢失对齐和配置变更回调：

- `Update` 只修改隔离候选值，校验通过并等待 frame 确认落盘后才发布；`Save` 是整体替换
  便捷入口，增删改命令优先使用 `Update`
- `Snapshot` 与 `Update` 候选值隔离 map、slice 和指针；保存失败或校验失败保持旧值
- 保存前读取当前文件，发现未 reload 的外部修改时拒绝覆盖；落盘成功但响应丢失时读取
  文件对齐，不再次执行修改回调
- `SetConfig` 用于启动装载和 `/pm reload`，只校验和发布，不再次保存
- 发布后调用可选 `ConfigChangeHandler[T].OnConfigChanged`；回调使用传入 ctx 递归修改
  会被拒绝，其他 goroutine 的并发修改按更新锁排队；回调失败保留已保存配置并进入
  `StatusApplyFailed`，业务暂停等待 owner 修复
- `Update`/`Save` 要求调用上下文具有 frame 写入的 owner 授权；后台任务和普通用户
  命令不能写配置

首次生成的零值配置不满足校验时进入 `StatusPending`：进程保留，Load/Start 拒绝进入
业务，只有 owner 命令可以继续修复。`StatusReady` 表示宿主配置已通过解码、标签和业务
校验并发布，不再只是构造值可读。

## 数据目录

`InitializeOptions.DataDir` 是宿主分配的根路径，frame 只传路径，不预先创建目录；R03
只校验输入非空，不读取也不创建该目录。
`plugin.Data` 的文件名必须是插件根目录内的相对路径；绝对路径、Windows 盘符、`..` 和
符号链接逃逸都必须被拒绝。只读不存在的目录返回 `fs.ErrNotExist`；只有创建/写操作才执行
一次 `MkdirAll`。R06 实现该行为，R02 不创建任何目录。

## 日志

插件直接使用标准库 `log/slog`，不定义私有日志 RPC。宿主最终日志使用可信字段：

```go
plugin.LogFieldPluginID
plugin.LogFieldPluginName
```

插件不能通过属性覆盖这两个字段。stdout 留给插件握手；R07 负责 slog 到 hclog/go-plugin
的结构化桥接、group/字段保留、启动失败标记和避免循环日志。

## 安全边界

- SDK 不导入 core，不公开 core 配置、会话、设备路径或登录凭据（Cookie、Authorization、
  票据）。
  `message.Media.Key` 和 `Message.Raw` 是已识别消息为下载、转发或排障所必需的业务字段，
  可能含敏感材料，只能交给当前插件，不得写日志或转存为宿主媒体仓库
- 插件不通过业务参数伪造 owner、账号、插件 ID、实例代次或后台身份
- 每个 Host 能力先检查当前连接和启用周期；Stop 后旧 context 或新调用都不能继续使用 Host
- 反向连接断开是终止状态，不允许通过再次 Start 恢复；必须结束旧进程并重新建立实例
- owner 判断由 frame 写入 `command.Authorization` 上下文，保存配置的 handler 必须读取同一
  可信上下文
- 未实现的能力返回 `Unimplemented`，缺少权限默认拒绝，不能返回空成功
- 有副作用的写操作在结果未知时标为 `OutcomeUnknown`，调用方不得自动重试
- 插件进程是本机管理员安装的可信代码；进程隔离用于故障隔离，不宣称是安全沙箱
