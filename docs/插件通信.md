# 插件通信

## R02 边界

R02 定义 Proto 服务和公开 Go 签名，尚不提供插件进程、gRPC 服务注册、go-plugin
握手或反向 Host 连接。R03 实现实例运行时；R05 实现配置控制；R07 实现日志桥接。
任何未实现的处理入口必须返回 `Unimplemented`，不能返回空成功。

## Proto 原则

- `proto/golem/sdk` 是唯一 wire 源
- 生成代码只在 `internal/wire`
- 消息结构化数据使用 `oneof data`
- 单条消息元数据使用显式字段，不使用 `Any`
- 媒体字节使用流，不进入一元 RPC
- 不定义消息、媒体、撤回或转发的 opaque business token
- 不定义 tenant、账号 epoch、实例代次或后台 token 字段
- 不维护旧协议兼容分支；frame 与 SDK 同步升级

## 插件方向服务

### PluginControlService

| 方法 | 输入 | 输出 | 语义 |
| --- | --- | --- | --- |
| `Describe` | Empty | `Descriptor` | 元数据、订阅、命令树、能力和默认配置 |
| `Initialize` | broker ID、配置、数据根路径 | `OperationResponse` | 绑定唯一 Host 连接和实例输入 |
| `Load` | Empty | `OperationResponse` | 可选 `OnLoad` |
| `Start` | Empty | `OperationResponse` | 可选 `OnStart` 并建立启用周期 |
| `Stop` | Empty | `OperationResponse` | 可选 `OnStop` 并取消启用周期 |
| `Unload` | Empty | `OperationResponse` | 可选 `OnUnload` 并释放实例 |
| `ValidateConfig` | `BytesValue` | `OperationResponse` | 严格校验候选配置，不修改状态 |
| `SetConfig` | `BytesValue` | `OperationResponse` | 校验、发布并触发变更回调 |

`InitializeRequest.data_root` 只是宿主分配的插件根路径，不是插件 ID，也不要求 SDK
立即创建目录。R03 负责 Host 和生命周期，R05 负责配置候选值，R06 负责路径安全包装。

### PluginBusinessService

| 方法 | 输入 | 输出 |
| --- | --- | --- |
| `HandleEvent` | `Event` | `EventResult` |
| `HandleCommand` | `CommandInvocation` | `OperationResponse` |
| `HandleCapability` | `CapabilityRequest` | `CapabilityResult` |

事件是一次调用输入，不持久化、不重放，也不分配可恢复游标。命令输入保留 frame 已词法
拆分的 `tokens`、原始文本、完整消息和 owner 标志；插件侧 R04 再用 Kong 完成参数绑定。

## 宿主方向服务

| 服务 | 方法 |
| --- | --- |
| `HostAccountService` | `Current` |
| `HostMessagesService` | `SendText`、`SendApp`、`SendMedia`、`Forward`、`Revoke`、`Download` |
| `HostContactsService` | `Find` |
| `HostChatroomsService` | `Get`、`Members` |
| `HostSessionsService` | `Acquire`、`Renew`、`Release` |
| `HostCallerService` | `Call` |
| `HostConfigService` | `Read`、`Save` |

所有请求都不携带插件 ID、账号 username、tenant 或业务授权 token。frame 从当前插件
连接确定调用者；R03 在连接身份之上完成授权和生命周期校验。`HostConfigService` 只读写
当前插件自己的 `config` 子节，不存在 revision、active 或 apply 状态。

## 消息流

`HostMessagesService.SendMedia` 是客户端流：

1. 首包 `SendMediaMetadata` 包含目标、消息类型、展示文件名、可选字节数、语音参数
2. 后续包只包含 `bytes data`
3. 图片、语音、视频和文件使用同一流契约；视频时长和封面提取由 core 适配层按现有能力处理
4. `size = -1` 表示未知；其他负数、声明总量与实收不一致、空流均无效
5. 插件拥有传入 `io.Reader` 的生命周期，SDK 不接管关闭责任

`Download` 是服务端流，每个成功包使用 `DownloadResponse.data` 返回字节；终止业务错误
使用 `DownloadResponse.error`，且必须是最后一个包。传输层断开仍由 gRPC status 表示，
不能伪装为正常 EOF。`Forward` 使用完整源 `Message`，`Revoke` 使用完整 `SendResult`，
`Download` 使用完整 `Message`；不先换取 token，也不由 frame 保存原消息或媒体对象。

## 错误

Wire 错误只携带：

- `Category`
- `Operation`
- 写操作 `Outcome`
- 脱敏 `Reason`
- 可选 `RetryAfter`

调用方按类别和写结果分支，不匹配文本。写请求已提交但响应丢失、超时或取消时为
`OutcomeUnknown`，不得自动重试。`OutcomeFailed` 只表示可确认目标写入未完成。

一元 RPC 的业务失败写入响应中的 `error` 字段，gRPC status 保持成功；连接、帧格式和传输
失败才使用非 OK 的 gRPC status。下载流的终止业务错误使用最后一个
`DownloadResponse.error`，随后正常结束流；不能把它编码成普通数据块或正常 EOF。

典型语义：

| 类别 | 场景 |
| --- | --- |
| `InvalidArgument` | 消息类型与 Data 不一致、选择器非法、整型/时长越界 |
| `PermissionDenied` | 非 owner、连接身份或资源范围不允许 |
| `NotFound` | 联系人、群、命令或能力不存在 |
| `FailedPrecondition` | 账号未就绪、插件未启用、撤回字段不可表达 |
| `ResourceExhausted` | 队列、并发或内联载荷超限 |
| `Unimplemented` | 契约已冻结但本任务尚未实现 |
| `Unavailable` | core、插件进程或连接不可用 |
| `Internal` | 上游响应违反契约或内部约束被破坏 |

## 生命周期（R03 目标）

```text
Describe
  → Initialize(Host, Config, DataDir)
  → Load
  → Start
  → Event / Command / Capability
  → Stop
  → Unload
```

R03 必须在业务初始化前取得安装目录和插件 ID 对应的 OS 排他锁；Describe 和校验共用
同一进程。`Base.Context()` 是启用期 context，后台 goroutine 必须从它派生，停用、断连
或卸载时取消。R02 只提供 `Runtime` 接口和 `Base` 字段，不声称这些行为已经可用。
