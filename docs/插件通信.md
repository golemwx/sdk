# 插件通信

## 当前边界

R02 定义 Proto 服务和公开 Go 签名；R03 已实现插件进程、gRPC 服务注册、go-plugin
握手、反向 Host 连接和实例生命周期。R04 已实现命令，R05 已实现配置控制，R06 实现数据
目录，R07 实现 slog 到 go-plugin 日志通道的桥接。任何未实现的处理入口必须返回
`Unimplemented`，不能返回空成功。

## Proto 原则

- `proto/golem/sdk` 是唯一 wire 源
- 生成代码只在 `internal/wire`
- 消息结构化数据使用 `oneof data`
- 单条消息元数据使用显式字段，不使用 `Any`
- 媒体字节使用流，不进入一元 RPC
- 不定义消息、媒体、撤回或转发的 opaque business token
- 不定义 tenant、账号 epoch、实例代次或后台 token 字段
- 不维护旧协议兼容分支；frame 与 SDK 同步升级

## 插件方向服务

### PluginControlService

| 方法 | 输入 | 输出 | 语义 |
| --- | --- | --- | --- |
| `Describe` | Empty | `Descriptor` | 元数据、订阅、命令树、能力和默认配置 |
| `Initialize` | broker ID、配置、数据根路径 | `OperationResponse` | 绑定唯一 Host 连接和实例输入 |
| `Load` | Empty | `OperationResponse` | 可选 `OnLoad` |
| `Start` | Empty | `OperationResponse` | 可选 `OnStart` 并建立启用周期 |
| `Stop` | Empty | `OperationResponse` | 可选 `OnStop` 并取消启用周期 |
| `Unload` | Empty | `OperationResponse` | 可选 `OnUnload` 并释放实例 |
| `ValidateConfig` | `BytesValue` | `OperationResponse` | 严格校验候选配置，不修改状态 |
| `SetConfig` | `BytesValue` | `OperationResponse` | 校验、发布并触发变更回调 |

`InitializeRequest.data_root` 只是宿主分配的插件根路径，不是插件 ID，也不要求 SDK
立即创建目录。R03 已实现 Host 和生命周期，R05 已实现配置候选值的严格解码、校验、
保存和发布，R06 负责路径安全包装。

### PluginBusinessService

| 方法 | 输入 | 输出 |
| --- | --- | --- |
| `HandleEvent` | `Event` | `EventResult` |
| `HandleCommand` | `CommandInvocation` | `OperationResponse` |
| `HandleCapability` | `CapabilityRequest` | `CapabilityResult` |

事件是一次调用输入，不持久化、不重放，也不分配可恢复游标。命令输入保留 frame 已词法
拆分的 `tokens`、原始文本、完整消息和 owner 标志；插件侧由 R04 的 Kong 封装完成参数绑定。

## 宿主方向服务

| 服务 | 方法 |
| --- | --- |
| `HostAccountService` | `Current` |
| `HostMessagesService` | `SendText`、`SendApp`、`SendMedia`、`Forward`、`Revoke`、`Download` |
| `HostContactsService` | `Find` |
| `HostChatroomsService` | `Get`、`Members` |
| `HostSessionsService` | `Acquire`、`Renew`、`Release` |
| `HostCallerService` | `Call` |
| `HostConfigService` | `Read`、`Save` |

所有请求都不携带插件 ID、账号 username、tenant 或业务授权 token。frame 从当前插件
连接确定调用者；R03 完成连接绑定和生命周期准入，frame 的 Host 实现负责业务范围授权。
`HostConfigService` 只读写当前插件自己的 `config` 子节，不存在 revision、active 或
apply 状态。

## 消息流

`HostMessagesService.SendMedia` 是客户端流：

1. 首包 `SendMediaMetadata` 包含目标、消息类型、展示文件名、可选字节数、语音参数
2. 后续包只包含 `bytes data`
3. 图片、语音、视频和文件使用同一流契约；视频时长和封面提取由 core 适配层按现有能力处理
4. `size = -1` 表示未知；其他负数、声明总量与实收不一致、空流均无效
5. 插件拥有传入 `io.Reader` 的生命周期，SDK 不接管关闭责任

`Download` 是服务端流，每个成功包使用 `DownloadResponse.data` 返回字节；终止业务错误
使用 `DownloadResponse.error`，且必须是最后一个包。传输层断开仍由 gRPC status 表示，
不能伪装为正常 EOF。`Forward` 使用完整源 `Message`，`Revoke` 使用完整 `SendResult`，
`Download` 使用完整 `Message`；不先换取 token，也不由 frame 保存原消息或媒体对象。

## 错误

Wire 错误只携带：

- `Category`
- `Operation`
- 写操作 `Outcome`
- 脱敏 `Reason`
- 可选 `RetryAfter`

调用方按类别和写结果分支，不匹配文本。写请求已提交但响应丢失、超时或取消时为
`OutcomeUnknown`，不得自动重试。`OutcomeFailed` 只表示可确认目标写入未完成。

一元 RPC 的业务失败写入响应中的 `error` 字段，gRPC status 保持成功；连接、帧格式和传输
失败才使用非 OK 的 gRPC status。下载流的终止业务错误使用最后一个
`DownloadResponse.error`，随后正常结束流；不能把它编码成普通数据块或正常 EOF。

典型语义：

| 类别 | 场景 |
| --- | --- |
| `InvalidArgument` | 消息类型与 Data 不一致、选择器非法、整型/时长越界 |
| `PermissionDenied` | 非 owner、连接身份或资源范围不允许 |
| `NotFound` | 联系人、群、命令或能力不存在 |
| `FailedPrecondition` | 账号未就绪、插件未启用、撤回字段不可表达 |
| `ResourceExhausted` | 队列、并发或内联载荷超限 |
| `Unimplemented` | 契约已冻结但本任务尚未实现 |
| `Unavailable` | core、插件进程或连接不可用 |
| `Internal` | 上游响应违反契约或内部约束被破坏 |

## 生命周期

```text
Describe
  → Initialize(Host, Config, DataDir)
  → Load
  → Start
  → Event / Command / Capability
  → Stop
  → Unload
```

`plugin.Serve` 在 go-plugin 握手和任何业务生命周期回调前读取插件元数据，并取得
安装根目录与插件 ID 对应的 OS 排他锁。锁路径固定为
`<install>/run/plugin-<id>.lock`；锁文件允许长期存在，进程退出后由操作系统释放锁。
Describe、Initialize 和后续业务调用都发生在持有锁的同一进程，frame 不启动第二套
“校验进程”。

插件日志不增加专用 RPC。`plugin.Serve` 把 `log/slog` 写到 stderr 上的 hclog JSON 通道，
go-plugin 宿主客户端解析后交给 `ClientOptions.Logger`；stdout 始终只用于握手。宿主覆盖
插件提交的同名字段并注入 `plugin_id`/`plugin_name`，因此业务日志不需要重复写插件 ID。

`Describe` 从实际实现的 `EventHandler` 和 `CapabilityProvider` 自动汇总订阅与能力，
从一次实际调用取得稳定快照并拒绝同一 Topic 的冲突模式。`Initialize` 只允许一次，
绑定当前连接唯一的 Host。`Load` 调用可选 `OnLoad`；`Start` 建立新的启用周期后调用
可选 `OnStart`；`Stop` 先关闭业务准入和 Host 访问，再取消启用周期并调用可选 `OnStop`；
`Unload` 完成停用排空后调用可选 `OnUnload`，随后由 frame 侧 `Client` 结束真实进程。

`Base.Context()` 是启用周期 context。OnStart 创建的后台 goroutine 必须从它派生，后台
Host 调用也必须携带它或由其派生的 context。Stop 会取消该周期；断连会取消周期并把实例
永久标记为不可用。忽略取消的 handler 不会被当作已经结束，Stop 会等待其真实返回。

### 实例锁

- 唯一键是规范化安装根目录与插件 ID；SDK 锁和 frame 安装目录锁职责不同，二者都需要
- SDK 使用操作系统文件锁，不使用内存 map、PID 文件存在性判断或锁文件删除作为释放信号
- 锁竞争返回失败并让子进程在业务初始化前退出；锁文件权限问题返回 `Internal`
- `GOLEM_PLUGIN_INSTALL_DIR` 可覆盖安装根目录；`GOLEM_PLUGIN_LOCK_PATH` 可覆盖完整
  锁路径，后者优先。两者都是部署输入，不是插件业务参数
- 进程崩溃、被结束或正常卸载后，OS 自动释放锁；遗留锁文件可以继续复用

### 错误与取消

- 未 `Start`、已 `Stop`、断连或卸载后的业务调用返回 `FailedPrecondition`
- `Stop` 不把调用方 context 的取消当作排空完成；它调用 OnStop 后等待 handler WaitGroup
- `Client.Unload` 即使卸载 RPC 超时或取消，也会继续结束子进程；未确认退出时返回错误
- 插件未声明 `Config[T]` 时 ValidateConfig 和 SetConfig 返回 `Unimplemented`
- 配置待修复或应用失败时，非 owner 命令、事件和能力调用返回 `FailedPrecondition`；
  owner 命令仍可执行以修复配置
- 插件未声明 `CommandProvider` 时 HandleCommand 返回 `Unimplemented`

## R10 退出确认协议

frame 与 SDK 只采用“结束旧进程再启动新进程”，不实现 go-plugin Reattach。以下规则是
跨仓库退出确认约定：

1. frame 先持有安装目录排他锁，并只启动一个插件子进程。子进程在握手和业务初始化前取得
   `<install>/run/plugin-<id>.lock`。
2. 停止流量后，frame 调用 `Client.Stop` 取消启用周期并等待在途 handler。Stop 超时只表示
   调用方不再等待，不表示 handler 已结束；不得因此复用旧周期。
3. frame 调用 `Client.Unload`。SDK 先请求 `OnUnload`，随后关闭反向 Host 服务并结束进程；
   `Client.Unload` 只有在卸载调用成功且 `Client.Exited()` 为 true 时才返回 nil。
4. `Client.Exited()` 是进程退出的权威确认信号。即使 `Unload` 返回错误，只要
   `Exited()` 为 true，就能确认进程已结束；错误描述的是 RPC 或 OnUnload，不是进程存活。
5. `Unload` 返回错误且 `Exited()` 为 false 时，禁止启动替代进程。frame 必须按已记录的
   PID、启动时间和可执行路径核验身份后终止该进程，并再次确认退出和 OS 锁释放。
6. 只有旧进程退出且插件锁释放后，frame 才能启动同 ID 的新进程。不得通过删除锁文件、
   检查 PID 文件是否存在或按进程名批量结束来实现单实例。
7. 正常 `SetConfig` 更新不重启进程；只有二进制替换或不可恢复进程故障才进入上述停旧启新。
8. 进程未确认退出的错误必须上报并停止加载该插件。无法确认 PID 归属时同样拒绝再启动。

推荐 frame 顺序：

```text
安装目录锁
  → 核验并结束遗留/当前进程
  → Client.Stop(ctx)（有界等待）
  → Client.Unload(ctx)
  → 轮询或读取 Client.Exited()
  → 确认 OS 锁可再次取得
  → 启动新进程
```
