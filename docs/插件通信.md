# 插件通信

T07/T08 提供插件启动、控制与业务 RPC、一条安全反向连接和实际执行跟踪。插件进程由调用方持有的 `rpc.Client`
拥有，SDK 不维护全局进程表，也不提供重新附加到旧进程的入口。

## 固定配对配置

| 项目 | 固定值 |
| --- | --- |
| ProtocolVersion | `1` |
| MagicCookieKey | `GOLEM_PLUGIN_MAGIC_COOKIE` |
| MagicCookieValue | `golem-sdk-grpc` |
| PluginSet 键 | `golem` |
| go-plugin 依赖 | `github.com/hashicorp/go-plugin v1.8.0` |

宿主使用 `rpc.HandshakeConfig()` 和 `rpc.PluginSet()` 取得独立副本，插件
`plugin.Serve` 复用同一内部定义。调用方不应在 frame 维护另一份配置。

cookie 只用于配对，不是运行权限凭据。普通发布、插件展示版本变化、新主题、新能力及
兼容的 Proto 新字段不改变配对值或协议版本。不兼容的通信结构或语义变更才提高唯一
ProtocolVersion，不增加版本目录、并行协议或版本匹配表。

## 插件入口

```go
package main

import "github.com/golemwx/sdk/plugin"

type Example struct{}

// Descriptor 返回固定声明
func (*Example) Descriptor() plugin.Descriptor {
    return plugin.Descriptor{ID: "example", Name: "示例"}
}

// main 运行插件服务，握手 stdout 由 SDK 管理
func main() {
    plugin.Serve(&Example{})
}
```

基础 Plugin 必须实现，生命周期按需实现。只实现 Loader 也会收到 OnLoad 和显式 Host，
未实现的生命周期按无操作处理。插件不要在握手阶段向 stdout 写业务内容；SDK 的
go-plugin 日志使用受控通道，默认丢弃，宿主可通过 `ClientOptions.Logger` 接收。

## 宿主启动

宿主构造 `rpc.ClientOptions`，填写尚未启动的 `exec.Cmd`、由文件名确定的 ExpectedID、
绝对 DataDir、非零 InstanceGeneration，以及当前账号代次和初始化配置。`Command.Env`
仅填写白名单环境变量，SkipHostEnv 会阻止继承宿主环境。

```go
options := rpc.ClientOptions{
    Command: exec.Command(pluginPath),
    ExpectedID: "example",
    DataDir: absolutePluginDataDir,
    InstanceGeneration: generation,
    AccountEpoch: accountEpoch,
    Services: rpc.HostServices{
        Host: hostBoundToInstance,
        Authorize: authorizeBoundInstance,
    },
    Validate: validateDescriptorAndPolicy,
}
client, err := rpc.Start(ctx, options)
if err != nil {
    return err
}
defer client.Close()
```

SDK 检查描述 ID 与 ExpectedID 一致，且显式授予的权限均为插件已经请求的权限。
Validate 在反向服务创建之前运行，frame 在此继续检查完整声明、重复名称及宿主策略。
数据目录由 frame 分配并创建，SDK 只传递绝对路径，不扫描或创建其他插件目录。

Start 默认以 10 秒覆盖整个初始化流程，并服从父调用更早的 deadline；生命周期
控制调用另有 5 秒上限。后续普通调用继续使用调用方 context，不替换成 Background。
`Enable`、`Disable` 和 `Unload` 显式调用可选生命周期。Unload 即使收到插件错误也会
回收资源；Close 无条件关闭实例，可重复调用，返回时子进程与反向服务已经退出。

启动顺序固定为：

1. 启动真实进程并完成唯一协议的 gRPC/mTLS 握手
2. Describe 并执行标识、显式授权和 Validate 校验
3. 在唯一 Broker 监听上注册七类 Host 服务及控制确认服务
4. Initialize 传递 BrokerID、控制凭据、权限、配置和实例上下文
5. 插件建立唯一反向连接并调用 ReverseReady，宿主确认控制凭据
6. 调用 OnLoad，成功后将客户端交给宿主

任一步失败都会回收已经创建的反向服务、连接及插件进程。Broker 服务构造保留
go-plugin 传入的 TLS 选项，不使用会丢失连接安全配置的空选项服务端。

## Host 服务与授权

反向连接同时注册 Messages、Contacts、Chatrooms、Sessions、Caller、Config、Account
七类服务。Host 业务实现由 frame 提供，SDK 仅转换公开领域类型；未提供的实现明确返回
Unimplemented。没有每能力 Broker、独立服务进程或额外媒体连接。

每个非控制的一元回调经过 `HostServices.Authorize(ctx, invocation, fullMethod)`。
没有 Authorize 默认 PermissionDenied；宿主构造服务时绑定实例身份，不从业务请求取得
可信插件身份。生命周期回调没有用户 invocation，仅能按宿主明确允许的独立授权
处理，不能把空 token 当管理员。SDK 保留 Authorize 附加的上下文值，并强制继承原请求的
取消和更早的 deadline，防止授权代码意外延长请求生命周期；业务实现继续校验具体用户、
会话与资源范围。

SDK 保留业务错误的 Category、Operation、InvocationID、Outcome 和 RetryAfter。
批量及分阶段失败同时保留结果和整体错误；缺失业务结果不会被当成空成功。
发送、回复或撤回发生传输失败时返回 OutcomeUnknown，调用方不得自动重试。

## 业务调用与执行完成

frame 调用 `Client.HandleEvent(ctx, invocation, event)`、`HandleCommand` 和
`HandleCapability`。`rpc.Invocation` 由宿主签发，ID 在实例内必须唯一且不可复用，Token
必须随机并绑定实例、账号、用户、会话、权限和调用链；插件没有设置可信身份的公共 API。
普通事件默认最多 5 秒，命令与能力最多 30 秒，并取父 deadline 的较早值。

wrapper 将凭据放入原调用 context，七类 Host 的 18 个一元方法自动从当前 context
取得凭据。派生 context 保留该身份及父取消，不需要插件在业务参数中手工复制 token。
SDK 宿主边界仅接受正在等待且未取消的调用凭据，并继续调用 `Authorize` 校验具体业务权限。
业务 RPC 正常返回、超时或取消都会撤销用户权限；插件即使保存旧 context 并剥离取消，
也不能再次借用该次用户身份。无 token 的调用仍按宿主独立后台授权处理。

普通事件、观察回调、会话通知和命令共用 4 个真实执行额度，被调用能力独立占用 2 个。
额度满立即返回 `ResourceExhausted`，不等待普通业务队列。控制操作不占两类业务额度。
用户代码直接在 gRPC handler 内运行，不为超时调用额外启动可无限累积的 wrapper 协程。
取消不会删除正在执行的记录，panic 会被脱敏并按实际退出处理。

通过 `ClientOptions.Services.ExecutionCompleted(ctx, invocationID, generation)` 接收真实
完成通知。完成通知绑定实例控制凭据和代次，使用独立实例控制 context，最长 5 秒，
不携带原用户 token，也不继承原业务取消。事件、命令、能力、生命周期和配置控制均使用
宿主分配的执行 ID；无请求字段的 ConfigDefaults 通过内部 gRPC metadata 携带控制执行 ID。
宿主必须按 ID 与代次幂等核销自身执行记录，忽略无匹配记录的通知，不能因旧代次通知释放新调用。

`Client.Drain(ctx)` 原子关闭新业务准入，取消后台周期，并返回稳定排序的在途执行 ID。
它不等待生命周期锁，因此忽略取消的 OnEnable 或业务 handler 仍能被查出。
handler 退出后先释放本地额度再发送完成通知；通知失败时宿主可再用 Drain
核对真实执行是否归零。业务 RPC 返回本身不能代替通知或 Drain，硬截止后的进程终止与
确认退出由 frame 的 T17 管理。Drain 后通过 Disable、Enable 开启新周期；配置屏障恢复
策略由 T22 接入，不能在 ConfigApply 后自动放行业务。

## 后台启用周期

OnLoad 显式收到 Host，其中 DataDir 是宿主分配的绝对路径。OnLoad 时 TaskContext 已取消；
每次 OnEnable 之前创建新的 `Host.TaskContext()`，它不随该次生命周期 RPC 返回而结束，
也不继承用户 invocation。禁用、Drain、卸载或反向连接失效都会取消它；启用失败或 panic
也会撤销新周期。启用 RPC 取消或超时会立即取消尚未提交的后台周期，即使 OnEnable
仍忽略取消继续运行，其真实执行记录仍保留。重新启用会替换成新 context，旧周期保持取消。

账号切换、账号失效及实例撤销时，frame 必须关闭准入并调用 Drain/Disable，或关闭实例，
不能只改变宿主内存中的账号代次而让旧插件后台继续运行。插件负责在 OnDisable 中等待
自身后台 goroutine 退出；SDK 只能发出取消，不能把取消本身当作后台工作已结束。

未实现的生命周期是空操作；声明了订阅、命令或能力却缺少对应业务接口时 Initialize
返回 `FailedPrecondition`，宿主清理已经创建的进程、连接和监听。

## 当前阶段边界

T07/T08 的七类 Host 一元方法、三类业务 handler、调用凭据及实际执行跟踪已接线，
并以人工数据和真实子进程验证。frame 的账号 epoch、用户/群资源范围、调用链和运行态
授权仍由 T09/T17/T20 实现，SDK 的有效调用检查不代替这些宿主策略。

SendMedia 和 Download 的流控、预算及取消回收属于 T26，当前明确返回 Unimplemented。
本阶段不连接 frame/core，不访问真实微信、模型服务或已有运行数据。

为避免 plugin.Serve 导入传输实现时形成循环依赖，固定声明的共享结构位于
`internal/contract`，公开入口仍为 `plugin.Descriptor` 类型别名；wire 转换仍集中在
`internal/wire`，生成类型不进入公开业务签名。

## 验证与依据

运行 `task proto`、`go test ./...`、`go vet ./...`。RPC 测试使用同一测试二进制的真实
子进程，显式就绪信号取代任意 sleep，检查双向 mTLS、默认拒绝授权、七类一元调用、
错误/部分成功、父调用取消和各启动失败路径的实际进程回收。

按工作区 AGENTS.md 和阿祖明确指令，本机不执行 race 检查；普通测试不表述为 race 通过。

实现按固定版本的 [go-plugin 客户端定义](https://github.com/hashicorp/go-plugin/blob/v1.8.0/client.go)
及 [Broker 安全服务构造](https://github.com/hashicorp/go-plugin/blob/v1.8.0/grpc_broker.go) 核对。
