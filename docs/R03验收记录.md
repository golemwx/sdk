## 真实子进程测试说明

测试夹具通过 `go build` 构建为真实可执行文件，再以独立进程由 `plugin.Start` 启动。夹具使用
文件标记记录 Load、Start、Stop、Unload、启用周期取消、Host 调用结果和事件处理起止，
测试读取这些标记验证实际执行顺序。

- 单实例与重载：同一安装目录并发启动两个同 ID 进程，恰一个成功；校验锁文件位于
  `run/plugin-subprocess-fixture.lock`；卸载后 `Exited()` 为 true，再启动第二个实例成功。
- 启动失败：`OnStart` 返回错误后 `Stop` 不会被伪调用；卸载仍启动真实收尾并确认退出。
- 忽略取消：事件 handler 忽略取消并睡眠，`Stop` 实测等待其返回后才成功。
- 断连：关闭 frame 侧反向 Host 服务后，实例取消周期、拒绝后续事件，并记录 Host 不可用。
- 数据目录：整个流程不创建 `plugins/data/<id>`。

## 代码自审与修复

完成实现后按 Standards/Spec 两轴复核了相对 R02 基线的完整 diff，并修复：

- 删除 Runtime 中未被 R05/R06 消费的私有 `dataRoot`、`initialConfig` 和仅测试读取的
  `runningHandlers`，避免为未来任务保留死状态。
- 删除 control server 中未使用的连接/watch context 字段，保留真正用于断连监视和取消的
  `remoteHostState` 与 `watchCancel`。
- `ClientOptions.Host` 改为必填，避免真实 Initialize 在无 Host 时静默成功。
- `Client.Close` 在 go-plugin 未确认进程退出时返回 `Unavailable`；`Client.Unload` 合并
  RPC 与退出确认错误，确保 frame 不会把“未确认退出”当作可重载。
- 修复 `Unload` 进入内部排空后二次检查调用方 context 的竞态；现在 context 在初次检查后
  过期也不会跳过在途 handler 等待，并加入确定性回归测试。
- 修正过期注释、Descriptor 复制说明和文件尾空白；移除 `internal/wire` 对 `plugin` 的
  反向依赖，Descriptor 转换留在 `plugin` 内。

没有发现需要改变冻结方案语义的跨仓冲突。
