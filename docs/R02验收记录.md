### 2.1 固定契约

- `Message` 含 `ID/Type/Sender/Receiver/Member/Content/Raw/Timestamp/Data`，
  `Raw` 使用 `BytesValue` 保留“缺失”和“显式空”的差异。
- `Data` 是封闭接口；八类实现只能使用指针：`*Text`、`*Image`、`*Voice`、`*Video`、
  `*Emoji`、`*Location`、`*App`、`*File`。
- `SendResult` 保留数值/字符串 `ClientID`、可选 `CreatedAt`/`ServerTime` 和写结果。
- `contact.Selector` 支持无前缀、`username::`、`nickname::`、`remark::`，按第一个
  `::` 分割，空值/未知前缀返回 `InvalidArgument`。
- `event.Subscription` 使用 `Observe`/`Consume`；`Result{Consumed}` 表达消费者结果。
- `command.Schema` 保留短参数、位置参数、重复参数、枚举、map、帮助和 owner scope；
  `command.Authorization` 是 frame 写入的 owner 上下文。
- `plugin.Host` 由 `Account/Messages/Contacts/Rooms/Sessions/Caller/Data` 七个小型接口
  组成；`plugin.Config[T]`、`Runtime`、`Data` 和日志字段先冻结签名，行为由 R03–R07 交付。
- 下载流使用 `DownloadResponse` 的 `data`/`error` oneof；上传流首包为唯一元数据，
  结束响应携带结构化错误。

## 4. 自审发现与修复

按代码规范、方案语义、无用代码和兼容残留两条线复核，发现后已直接修复：

1. `Raw` 原先是裸 `bytes`，无法保留缺失与显式空；改为 `BytesValue raw` 并增加存在性往返测试。
2. `Text` 值类型会允许非指针 Data 值，和封闭指针实现不一致；改为 `*Text`。
3. `Message.Type` 与 oneof `Data` 实际类型不一致时原先可能静默通过；双向转换统一返回
   `InvalidArgument`。
4. Proto 整型、媒体时长和错误 `RetryAfter` 原先存在截断/饱和风险；增加范围校验，覆盖
   `time.Duration` 溢出和负数。
5. `SendResult.Revocable` 现在要求成功写结果、非零 NewID/ClientID、接收方、有效创建时间
   和可解析的非零 uint64 ClientID；零值和超出 Proto Timestamp 范围的时间返回 false。
6. 命令 schema 补齐 `Short`、`Positional`、`Map`、`Enum`，并避免把 map 描述成重复参数。
7. 下载服务端流原先没有结构化业务错误通道；增加 `DownloadResponse.data`/`.error` oneof，
   明确传输中断仍使用 gRPC status。
8. 文档原先错误地把 `Media.Key`/`Raw` 说成不可公开，和 R01 真实媒体字段矛盾；改为
   “只交给当前插件、不得记日志/转存”的敏感字段规则。
9. 账号事件没有重复 payload 的歧义已明确为 `Host.Account.Current` 查询；事件改为只读输入
   语义。
10. 删除未使用的 go-plugin/hclog 直接依赖，`go mod tidy -diff` 无输出；删除旧空包和
    仅用于旧实现的测试。

没有发现需要改变冻结方案语义的冲突，也没有把未实现的 R03–R07 行为写成可用。
